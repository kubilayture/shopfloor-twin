# Phase 04 – MES foundation: historian and equipment states: log

Dated entries, one per merged pull request: what merged, what was learned, deviations from the plan.

## 2026-10-15

- Phase 4 planned: issues #92–#101, milestone 5.
  - The simulator's shift calendar becomes a shared package, so that the MES cuts shifts exactly as the simulator does.
  - Ingest keeps ADR-0015's dedup in the database (unique keys) and uses a persistent MQTT session.
- The plan review (PR #102) found three blockers, all adopted:
  - hypertable unique keys must include the time column;
  - the MES needs a starting state (retained messages and snapshots anchor it);
  - a simulator restart moves simulation time backwards, so intervals are scoped per epoch.

  Also adopted: a plant watermark for provisional closing, UTC hours, a session expiry for the persistent session, a cursor table, `db/migrations` as in plan section 8, the interval functions in `oee-core`, and window-only recomputation.

- Merged #102 (#92): Phase 4 plan.
- #93: the migration runner is about 80 lines with an advisory lock, checksums and a transaction per file; tests start a real TimescaleDB and cover a concurrent start, a changed file, an unknown migration and a rollback. The Docker-context helper moved to `@shopfloor/test-kit/docker` for the gateway and the MES.
- #93 review and CI: the gateway end-to-end test timed out in CI once the MES tests (a second database container) ran beside it. End-to-end tests (`*.e2e.test.ts`) now run in their own CI job, one at a time, and their waits say what they waited for. Migration runner: no-transaction files (PostgreSQL runs a multi-statement query as one implicit transaction, so they are split into statements), LF-normalised checksums, a lock wait limit, and a column list typed from `Database`.
- CI again: the outbox outage test (#78) timed out under the same load. The gateway and MES test files now run one after another (`fileParallelism: false`); they start processes and containers.
- Merged #103 (#93).
- #94: the calendar moved without any behaviour change; the golden week is byte-identical. `shift-calendar` and `oee-core` are pure packages (lint-enforced). A property test checks that the shift bucket is constant between consecutive cuts and changes at each one, over a whole week.
- #95: ingest stores every message in a transaction inside MQTT.js's `handleMessage`, whose callback gates the PUBACK, so a message is acknowledged only after the commit, in arrival order (ADR-0017). Tests run a real TimescaleDB and Mosquitto: duplicates, out-of-order facts, retained messages, stale epochs, invalid payloads, a gap that becomes an incident and is filled late (also across a restart), a failed transaction retried, and an MES crash inside a transaction with the broker queueing for the persistent session: all twenty facts stored exactly once.
  - Deviation: a snapshot carries the gateway's epoch, not the device's, so "first anchor per (equipment, epoch)" became "per (equipment, device epoch)", with a snapshot taking the epoch of the next device fact of its equipment (ADR-0017).
  - Added beyond the issue: `ingest.component_status` (the gateway's latest status) and a pool error handler, so an idle database connection closed by the server no longer ends the process.
  - Known limit: one transaction per message; draining a long outage's queue may take minutes (not measured yet).
- #95 review (PR #105), all adopted:
  - poison messages: a value the database can't store blocked ingest in an endless retry. Failures are now classified by SQLSTATE: transient ones are retried and, if the database stays down, the session is dropped deliberately until it answers (a blocked MQTT.js pump doesn't even read PINGRESP); data errors are recorded as `unstorable` and acknowledged. Validation refuses times outside 1970–2199 and lone surrogates; `lost` is BIGINT;
  - snapshot anchors could take the wrong epoch (a stale retained snapshot on a persistent broker) or none (a silent machine): snapshots now carry an optional `deviceEpoch` (UNS contract 1.1), filled by the gateway; older snapshots fall back to the next fact, latest one only;
  - the queue sizing was wrong: 100,000 messages is about one hour at the real ~25 messages/s at 60× (the plan's "5 hours" overstated it), and draining it takes about two minutes at the measured ~1,000 messages/s;
  - hypertable chunks are 7 days (1 day of simulation time made about 60 chunks per wall day at 60×);
  - a known stream's new epoch counts numbers below its first one as a gap;
  - any broker user can take over client id `mes-server` (documented; the plain ACL can't prevent it);
  - a test for a crash between commit and acknowledgement.
- #95 re-review: "an unknown error three times is unstorable" lost good facts behind a held lock (`55P03`), and the same would happen during a deploy (`42P01`). Now only SQLSTATE classes 22, 23 and 54 are unstorable; every other error is retried and then suspends the session, never acknowledged. The cursors are reloaded before reconnecting, so a commit that was applied although it reported failure is a duplicate on redelivery. A test holds an `ACCESS EXCLUSIVE` lock against a 200 ms `lock_timeout`.
- #96: the `equipment` module stores state intervals in `equipment.equipment_state_interval` (a hypertable), every piece inside one UTC hour and one shift bucket, with the opening fact's `seq` and a `provisional` flag for the open interval (ADR-0018).
  - Reconciliation without a broker: the headless simulator runs as a process (apps never import each other), its event log is mapped to the UNS messages the gateway publishes (one device sequence per machine across state, cycle and alarm, as OPC UA `Sequence` and the washer's ring number them; a snapshot per machine at start, everything starting Off) and fed through ingest's store path (`Ingest.deliver`, new) into TimescaleDB. The golden week equals the ground truth per machine and shift bucket to the millisecond, in order and shuffled with 10 % duplicates, and both runs store identical rows. The week takes about three minutes, so it runs in the end-to-end job; `pnpm test` reconciles a Friday with its night shift (about 40 s).
  - Epochs: all simulated devices share the simulator's epoch, so cycles and states of any machine move the plant watermark; telemetry carries the gateway's epoch and counts for its equipment's newest device epoch.
  - `shiftKeyAt` per piece would have cost about 54 µs each; `shiftSegments` (new in `shift-calendar`, property-tested against `shiftKeyAt`) walks the calendar once per window.
  - Performance: the first version added about 3.8 ms per state fact (a window query and a five-statement transaction); an in-order fast path and a single upsert-and-delete statement bring it to about 1.4 ms. Storing open intervals every simulated minute dominated a replay, so replays use an hour step (boundaries still trigger).
  - Ingest change: a fact already in the table but unknown to the cursor (a commit reported failed but applied) is now re-announced to listeners, which otherwise never heard of it.
- #96 review (PR #106), all adopted:
  - blocking: a restarted simulator's telemetry arrives before the collector's resync publishes the new snapshot, so it was credited to the old epoch (an old interval became 46 hours of final Running; after an MES restart old open intervals moved a day). Telemetry now carries an optional `deviceEpoch` (UNS contract 1.1), filled from the same Modbus read or the OPC UA connection's resync; telemetry without it never moves a watermark, and a closed epoch's end (`interval_source.closed_at`) never moves again;
  - a clamped (equipment, epoch) is recomputed once, then handled window by window with clamped neighbours, instead of in full on every fact inside ingest's acknowledgement path;
  - the fact count is taken from ingest for reordered facts, so a fact handled twice no longer makes every start recompute; a start also accepts an open interval that has no piece yet;
  - a track marked for recompute is never patched from its stale state; the re-announce also re-sends the epoch's anchor;
  - ADR-0018 corrected, with a note on retention; per-test limits of the golden week (4 and 6 minutes) stay inside the end-to-end job's 20 minutes; the Friday test now starts at 14:00 (about 25 s).
- Merged #106 (#96).
- #97: the `realtime` module serves the read-only REST API under `/api/v1` and WebSocket push at `/api/v1/ws` (ADR-0019).
  - Routes are declared once with zod: zod validates path and query (dates parsed, unknown parameters refused, ranges bounded), the response schema types the handler, and the converted schemas give an OpenAPI 3.1 document (`docs/api/mes.openapi.json`, drift test). Errors are RFC 9457 problem details; 5xx details never carry the cause.
  - Intervals are returned merged: the stored hour and shift pieces of one interval are joined back and clipped to the range. Telemetry is decimated by `time_bucket` (min, max, average, count per bucket, at most 5,000 buckets) so a week fits a chart.
  - Push: ingest awaits its listeners before the broker acknowledgement, and the equipment module's changes are announced inside that path, so the push listeners only queue a delta per client and key and flush on a later event-loop turn. A slow client's queue is coalesced (one delta per key) above 256 KiB buffered and the client dropped above 4 MiB or after a missed pong.
  - Measured: the 60× rate (25 messages/s, a third of them state changes) reaches a WebSocket client within about 30 ms at most locally (exit criterion 3 allows 2 s).
  - Deviations: `GET /shifts/{date}/{shift}/totals` instead of `/shifts/{shiftKey}/totals` (the key contains a slash); the slow-client coalescing is tested with a fake socket (a real one needs megabytes in the kernel's buffers before `bufferedAmount` grows), the rest of the protocol with a real WebSocket client. Master data's equipment list now includes the site; ingest's sample notices carry telemetry values.
- #97 review (PR #109), all adopted: the per-client subscription limit now counts every new metric (adding metrics to a subscribed equipment bypassed it), plus a per-client rate limit on messages; the API reads through its own pool (4 connections, 5 s `statement_timeout`, timeouts answer 503) so dashboard reads can't take connections from ingest's acknowledgement path; unsubscribing one metric of an equipment subscribed whole is refused; no snapshot after an unsubscribe; a telemetry snapshot holds back only that equipment's telemetry; a truncated interval list drops the intervals that may continue and gives `next`; impossible shift dates are 400 and unknown shift ids 404; `Host` and WebSocket `Origin` allowlists (`HTTP_ALLOWED_HOSTS`, `HTTP_ALLOWED_ORIGINS`) against DNS rebinding and cross-site sockets; push tests use fake timers.
- #98: `apps/web` with the plant overview and machine detail (ADR-0020).
  - API typing: the response and WebSocket message zod schemas moved from `mes-server` to `@shopfloor/contracts/mes-api`; the OpenAPI drift test passed unchanged, and `web` parses every REST answer and pushed message with them (plan section 8: unknown at boundaries, then zod). Generating types with `openapi-typescript` was rejected: no runtime validation, and a generated file to keep in step.
  - Code-based routes: two routes, nothing generated.
  - Live data: one `LiveClient` per tab (reference-counted subscriptions, resubscribe after reconnect, backoff 0.5 s to 15 s with jitter, 5 messages/s in bursts of 8 against the MES's 10/20, retries after `busy`, `rate-limited`, `unavailable`); states, clock and telemetry go into the query cache under `['live', …]`; the newer of REST and pushed state wins (epoch, `seq`, start); REST queries are refetched after a reconnect. A pushed state reaches the screen after TanStack Query's batched notification (a 0 ms timeout), far inside exit criterion 3's 2 s.
  - Dev proxy and the MES allowlists: `changeOrigin` sends the MES's host; for the WebSocket the proxy rewrites `Origin` only when the page comes from the dev server itself, so other sites stay refused. Checked with `vite preview` against a mock MES that applies the same Host and Origin checks: the overview went live, the detail drew the timeline and trends, at desktop and phone width.
  - Deviations: shift totals per state are computed from the intervals of the selected range instead of `GET /shifts/{date}/{shift}/totals`, because the API has no "current shift" lookup and the shift calendar needs Temporal, not yet in every browser; Vite 8.3.4 (released 2026-10-08) is the version Vitest already resolved, pinned to avoid a second Vite, while the other new web dependencies are at least two weeks old; component tests use jsdom, not Vitest browser mode (plan section 9), until Playwright arrives with #100.
- #98 review (PR #110), all adopted:
  - CI: two web tests ran into the 5 s timeout beside the Testcontainers suites. Causes: every live sample copied the whole sample array and TanStack Query's structural sharing compared the whole buffer again (quadratic over a session), and role queries computed every element's style while polling. Samples are now appended in place (O(1) amortised, binary-search insert for late ones, batch trimming) with structural sharing off for `['live', …]`, Testing Library skips the visibility check (`defaultHidden`), and the screen tests wait on test ids; `testTimeout` 15 s as a margin. Under twice as many CPU-burning processes as cores the slowest web test takes about 0.5 s.
  - Blocking: trend lines broke at every sample at 60× (gap threshold three buckets, 18 s for 1 h, while OPC UA samples arrive every simulated minute). The threshold is now three times the median spacing of the points, at least three buckets.
  - Blocking: the dev and preview proxy let a rebound name (`Host` and `Origin` `evil.test:4173`) open the WebSocket, since `changeOrigin` satisfied the Host allowlist, Vite's host check skips proxied upgrades and the Origin was rewritten. The proxy now refuses upgrades with a non-loopback `Host` (403) and rewrites the Origin only for loopback names; checked against `vite preview`.
  - The timeline had a hole at its live end between interval reads; a pushed state change of the machine rereads them (throttled to 2 s).
  - A subscription re-queued by a retry after it was sent leaked on the server when released; each subscription now records whether it was sent on the current connection.
  - Live telemetry is dropped a minute after its screen closes; the metrics table's latest values follow pushes; band keys include the epoch.
  - Accessibility: time without data is hatched on the timeline (Idle and other light states were indistinguishable from the empty track); focus moves to the new screen's heading after navigating; states are not marked stale while the page first connects.
- #99: Compose services `mes` and `web`.
  - `apps/mes-server/Dockerfile` follows the simulator and gateway images (Node 26 Alpine, `pnpm install --prod --ignore-scripts --filter`, non-root, healthcheck on `/health/ready`) and adds `db/migrations` and `config/plant`; it migrates at start-up (ADR-0016). `apps/web/Dockerfile` builds with Vite and serves `dist/` from `nginxinc/nginx-unprivileged:1.30.6-alpine3.24` (stable branch, non-root). Images: MES 314 MB, web 94 MB.
  - nginx forwards `Host $http_host`, with the port: the MES's same-origin check compares the WebSocket's `Origin` host and port with `Host`, so `$host` (the README's earlier suggestion) would have refused every WebSocket. The default `HTTP_ALLOWED_HOSTS` already covers `localhost` and `127.0.0.1`, so `HTTP_ALLOWED_ORIGINS` stays empty. nginx resolves `mes` through Docker's DNS every 10 s instead of once at start, so a recreated MES is found again (and nginx starts without it).
  - CSP without `unsafe-inline` works with Vite's output: checked in a browser on the overview and the detail with both uPlot charts (no violations; uPlot and React set styles through the DOM).
  - The database password reaches the MES as `PGPASSWORD` (node-postgres reads it when the URL has none), not inside `DATABASE_URL`: a base64 password may contain `/` or `+`, which would need URL encoding.
  - Start order: the default stack keeps the gateway independent of the MES (retained states and the MES's persistent session make the overview complete whenever it joins); #100 drives the plan's stricter order with `SIM_AUTOSTART=false` itself.
  - Dockerfile guard: `scripts/check-dockerfiles.ts` in `pnpm verify` derives the workspace packages each image installs and runs from the `package.json` graph and compares them with the Dockerfile's `COPY` lines (missing and superfluous). With the #94 mistake re-created (the simulator without `shift-calendar`) it fails naming both missing lines.
  - Stack smoke: MES ready; the app shell with SPA fallback, CSP, caching and gzip; all six machines' current states through `/api/v1/equipment` on the web; a `states` snapshot over the WebSocket through nginx; a foreign `Host` (403) and a foreign `Origin` (refused) through the web. The web checks run on the host with Node's built-in `fetch` and `WebSocket` (`scripts/stack-smoke-web.mjs`), so a request carries the `Host` and `Origin` a local browser sends; CI's stack job sets up Node for it.
  - Memory at 60× (Colima, 2 GiB VM): db 61 MiB, broker 4, simulator 190, gateway 94, MES 79, web 9; about 440 MiB in all, with the VM at about 830 MiB used (another project's database included). Limits add up to about 2 GiB with the database's tuning, and Testcontainers suites run beside the stack, so the runbook recommends a 4 GiB VM (owner item).

## 2026-10-16

- #100: full-shift reconciliation through the whole chain, and Playwright on the live overview.
  - The simulator keeps the headless `GroundTruth` in live mode (fed by the same events, read-only) and serves it as `GET /api/v1/ground-truth` (control API 1.1): the `summary.json` shape up to the processed simulation time, plus epoch, current bucket, complete buckets and each machine's current state. Golden snapshot unchanged; a test checks that a live run read every few seconds emits the same events as one never read and that its completed buckets equal the headless summary.
  - `pnpm test:reconcile` (`e2e/`, a plain Node script, since the stack, the shift and the browser check run side by side) drives the plan's start order on the real images under its own Compose project: db and broker, MES ready, simulator idle and gateway connected with every machine's start-up state anchored in the MES (Off at 06:00), web; then resume at 60× from Monday 06:00 with the golden week's seed. The gateway's `depends_on` needs the simulator up, which is fine: idle, it publishes nothing but its start-up state. Playwright samples the overview for 90 s during the shift.
  - Measured locally (M3, Colima VM with 2 CPUs and 2 GiB), two consecutive runs, both green: 541–568 s in all (image builds 22–48 s from cache, MES ready 11.5 s, gateway connected 11.5 s, web 6.9 s, shift 486 s, drain 2.6 s, comparison 0.4 s). The shift ran at an effective 60.00× (29,151 s simulated in 485.9 s); the simulator's lag (`GET /api/v1/status`, sampled every second): mean 1.0–1.1 ms, p95 2.4 ms, max 3.3–15 ms. After pausing at 14:05:51, the MES's watermark equalled the simulation time within 2.6 s.
  - **Exit criterion 1:** for shift `2026-10-12/A`, time per state per machine from `GET /api/v1/shifts/2026-10-12/A/totals` equals the live ground truth to the millisecond for all six machines in both runs (for example asm-01: Running 26,200,412 ms, Stopped 501,429, Starved 298,159, PlannedStop 1,800,000; wsh-01: Running 12,283,112, Stopped 6,769, Starved 9,396,743, Blocked 5,313,376, PlannedStop 1,800,000), and the live ground truth equals the golden week's shift A. All 1,221 stored pieces lie inside one UTC hour and one shift bucket. No data-quality incidents at all (no start-up gap with this order) and no rejected messages. Three machines' shift-A totals include provisional time (asm-01 2,272,483 ms, cnc-01 877,255, cnc-02 380,554): the interval each was in at 14:00 is still open, but its shift-A piece ends at the boundary and can't change once the MES has that machine's facts up to the boundary, which the drain check verifies (its current state and start equal the simulator's). The plant-wide watermark alone wouldn't show that: a busy machine moves it past a silent one's late facts.
  - **Exit criterion 3:** Chromium on the Compose `web` saw each machine's latest state within 2 s for every judged change: 203 and 200 state changes in 90 s, delay p50 102–109 ms, p95 217–254 ms, max 281–292 ms; no violations. Rule: when the truth changes at t, the page shows that state or one the truth took later by t + 2 s (skipped intermediate states allowed); the page records its badges every 20 ms, and a change's time is when the paced clock reached the state's start. Review follow-up: the page must also really change (at least half as many transitions as judged changes, and one on every machine whose truth changed), since a frozen page could match changes back to the state it shows; a change's time comes from one `/ground-truth` answer (its new `pacedTime`, at the request's midpoint) instead of mixing it with `/status`.
  - **Exit criterion 4 (part):** the reconciliation is its own CI job `reconcile` (about 15–19 minutes: install, browser libraries, cold builds, about 1 minute of start-up, 8 minutes of shift; job timeout 30 minutes after review, and the run stops itself after 25 with its report and logs, which are uploaded also after a cancellation); its CI time is recorded when it first runs on the pull request.
  - Deviations: Playwright installs only Chromium's headless shell (`--only-shell`), which headless runs use, instead of full Chromium (about half the download). Shift A's totals are compared when they no longer change, not only where no piece is provisional (see above). After review, the images are tagged by `IMAGE_TAG` (`dev` by default, `reconcile` for the run), so a run no longer replaces the dev stack's images; SIGINT and SIGTERM remove the stack and the env file with its passwords.
