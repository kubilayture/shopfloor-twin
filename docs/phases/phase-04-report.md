## Review findings that mattered

Every pull request had an independent review (ADR-0011). The findings below changed the design, not only the wording.

- **Plan (#102):** three blockers, all adopted before any code: a hypertable's unique key must include its time column; the MES needs a starting state (retained messages and snapshots as anchors); a simulator restart sends simulation time backwards, so intervals are scoped per epoch.
- **Migrations (#103):** the column list typed from `Database`, so drift fails `tsc`; transaction control in files refused and a `no-transaction` marker added (PostgreSQL runs a multi-statement query as one implicit transaction); LF-normalised checksums.
- **Shift calendar (#104):** the simulator image lacked the new package (found by CI's stack smoke, then guarded for good in #99); overlapping shifts disagreed with the ground truth and are now rejected by the plant config.
- **Ingest (#105), blocking:** a value the database can't store blocked ingest in an endless retry. The re-review then found that the first fix, "an unknown error three times is unstorable", would acknowledge good facts behind a held lock (`55P03`) or during a deploy (`42P01`). Only SQLSTATE classes 22, 23 and 54 are unstorable now; everything else is retried and then suspends the session. Snapshots gained `deviceEpoch` (UNS contract 1.1), and the broker queue sizing was corrected (see Deviations).
- **Equipment (#106), blocking:** a restarted simulator's telemetry arrived before the new snapshot and was credited to the old epoch, turning an old interval into 46 hours of final Running. Telemetry gained `deviceEpoch` too, and a closed epoch's end never moves again. Recomputation of clamped tracks left the acknowledgement path.
- **API (#109):** the subscription limit could be bypassed metric by metric; the API got its own pool with a statement timeout, so dashboard reads can't starve ingest; Host and Origin allowlists against DNS rebinding and cross-site sockets.
- **Web (#110), two blocking:** trend lines broke at every sample at 60× (gap threshold now three times the median spacing); the dev proxy let a rebound host name open the WebSocket. Also a quadratic copy of live samples that timed out web tests beside the Testcontainers suites in CI.
- **Containers (#111):** nginx stopped with SIGQUIT and waited for open WebSockets until Docker killed it (now SIGTERM); duplicate `Cache-Control`; the smoke's foreign-Origin check now requires the upgrade itself to fail.
- **Reconciliation (#112):** a frozen page could pass the Playwright check (now it must show real transitions); latency was timed from processed simulation time, which can lag the paced clock by up to 1 s (now one `/ground-truth` answer with its `pacedTime`); CI timeout, interrupt clean-up and separate image tags.

## Known issues and carry-overs

- **#113 (open): interval finality per piece.** A finished shift's totals can still report provisional time (about 38 minutes for asm-01 in shift A), although that time can no longer change. Phase 5 should fix this before OEE reads shift totals as final.
- **Phase 5 inherits:**
  - `equipment.equipment_state_interval` with every piece inside one UTC hour and one shift bucket, ready for hourly and per-shift aggregates;
  - `oee-core` with the interval functions, to be extended with OEE;
  - the reconciliation harness (`pnpm test:reconcile`, CI job `reconcile`), to be extended to OEE against the ground truth;
  - the `realtime` API and the web app, for the OEE dashboard and downtime coding.
- **One transaction per message** in ingest: about 1,000 messages per second is ample now, but batching is the first lever if a longer outage or a faster plant needs it.
- **Client-id takeover:** any broker user can take over `mes-server` (as `gw-01` in Phase 3); accepted until Phase 9 (dynamic-security plugin).
- **Broker persistence:** queued messages for the MES's persistent session survive a broker crash only up to the last autosave.
- **Retention:** no retention or compression policy on the hypertables yet (ADR-0018 notes what a retention policy must respect).
- **`prom-client` is deprecated** upstream in favour of `@prometheus-io/client`: a follow-up for ADR-0012, still open.

## Lessons

- **Reviews found the flaws that only show under failure or restart**, as in Phase 3:
  - a poison message blocking ingest forever, and then a fix that would acknowledge unstored facts behind a lock (#105);
  - telemetry credited to a dead simulator run, making a 46-hour interval (#106);
  - a dev proxy that let DNS rebinding through (#110);
  - a Playwright check a frozen page could pass (#112).

  Asking reviewers to _run_ a restart, a lock or a rebound host name found them; reading the code didn't.

- **Classify errors by what a retry can change.** SQLSTATE classes say it: data and integrity errors (22, 23, 54) never heal, everything else might. "Three failures means poison" is a guess that loses data.
- **Prove with the strongest equality available.** Shift totals equal to the millisecond against an independent ground truth, every piece inside its hour and shift, no incidents. A tolerance would have hidden the provisional-time question that became #113.
- **Measure before sizing.** The plan's "5 hours of queue" was a calculation from an assumed rate; the measured rate made it 1 hour. The first interval implementation cost 3.8 ms per fact; measuring found the window query and brought it to 1.4 ms.
- **CI load is a test condition.** Three CI failures came from suites starving each other (a second database container, Testcontainers beside web tests); `fileParallelism: false`, a separate `end to end` job and fixing a quadratic copy each solved one.
