## [Unreleased]

### Added

- Web login, account, user administration and role-aware screens (#170; ADR-0026 and ADR-0020 notes).
  - **Login:** `/login` with `redirect` (only a path of this app, `safeRedirect`) and `reason` (`ended`, `idle`, `logout`); a temporary password is changed there before any other screen opens. A 401 from REST or a WebSocket close 4401 goes to `/login` and back to the page after the login; a 403 `password-change-required` or a close 4403 to the forced change. The live client stops on 4401/4403 (no reconnect) and starts after the login.
  - **Account and users:** `/account` (user, roles, permissions, session times, password change, logout); `/admin/users` for `user:admin` (create with a generated 16-character temporary password shown once, roles, enable and disable, reset password). The header shows the user and **Log out** (ends the session at the MES, empties the query cache, stops the live client); **Users** only for admins.
  - **Roles on screen:** screens hide the writes the session's roles lack (`useCan`, `ROLE_PERMISSIONS`).
  - **Drafts:** forms register unsaved input (`useUnsavedDraft`); a session lost while a draft exists keeps the page, inert and covered, under a login for the same user only (logging in as someone else discards the input).
  - **Idle timeout:** a person's input (pointer, key, wheel, touch) in any tab of the browser counts as use (`localStorage` `shopfloor.lastActivity`), pushed messages and background refreshes don't; a warning 2 minutes before the end with **Stay logged in**, then the web logs out itself (`reason=idle`); a keepalive `GET /session` at most every 2 minutes while someone types; the 12 h absolute limit is warned too.
  - **Routes** split into one file per area under `apps/web/src/routes/`; the login gate decides by the matched route, not the location.
  - **Test logins:** the stack smoke creates a per-run operator `smoke-<hex>` with `user:create` (generated password on stdin) and checks anonymous 401, WebSocket 4401 and a missing permission 403, and with `SMOKE_WRITES=1` and `MES_BOOTSTRAP_ADMIN_PASSWORD` the bootstrap admin's forced change (403, 4403) and writes audited as the session user; the reconciliation generates `MES_BOOTSTRAP_ADMIN_PASSWORD`, whose admin changes its password and creates `reconcile-supervisor` through the API (`provisionUsers`); the Playwright checks log in through `/login`, and every write refusal set checks "no session → 401". CI's smoke `.env` generates `MES_BOOTSTRAP_ADMIN_PASSWORD`.
- Database roles and one audit log (#169, ADR-0027; ADR-0016 and ADR-0022 amendments, ADR-0023 note; migrations `0017`–`0019`).
  - **Roles:** `mes_owner` (no login) owns every schema, table, view, sequence and function; `mes_cagg` (no login) owns `equipment.state_hourly` and `ingest.cycle_hourly`, reads their sources and has no `CREATE` anywhere; `mes_app` (login, `DB_APP_PASSWORD`) is what the MES connects as, owns nothing and is a member of `mes_cagg` WITH INHERIT FALSE, SET TRUE. As `mes_app`, `ALTER TABLE … DISABLE TRIGGER`, `TRUNCATE`, `UPDATE` and `DELETE` on the append-only tables, `DELETE` on handover notes and `CREATE` in a module schema are refused (42501), also after `SET ROLE mes_cagg`.
  - **`migrate` step:** `pnpm --filter @shopfloor/mes-server migrate` and the Compose one-shot service `migrate` (the MES image) connect as `DB_USER`, create or update the roles (`mes_app`'s password from `DB_APP_PASSWORD`, never logged) and run each migration under `SET LOCAL ROLE mes_owner`. The MES no longer migrates: it starts after `migrate` succeeded, connects as `mes_app` and is not ready while the migration history differs from its own (`migrationStatus`).
  - **Aggregates (B1):** `0017` moves both to `mes_cagg` as the superuser and grants `mes_app` `SELECT` as `mes_cagg`; the refresher runs `SET ROLE mes_cagg`, the `CALL`, `RESET ROLE` on its own connection; no policies.
  - **Existing databases (M1):** `0017` moves every object of a database the MES migrated itself to `mes_owner` one by one (`REASSIGN OWNED` fails with 2BP01); tested on a database migrated to `0015` the old way, and on the Compose stack over one migrated to `0016`.
  - **Grants:** `DECLARED_GRANTS` (`apps/mes-server/src/db/grants.ts`, typed from `Database`) lists every grant per role and object, the aggregates included; a test compares it with the database (`_timescaledb_internal` excluded), and `docs/data-model.md` gains a "Roles and grants" table.
  - **One audit log:** `Identity.audit(trx, …entries)` writes every module write into `identity.audit_log` in the write's transaction (entities `downtime-coding-set`, `alarm-occurrence`, `alarm-point`, `handover-note`; actions `downtime.code|clear|orphan`, `alarm.ack|comment|shelve|unshelve`, `note.create|edit`); `Identity.auditEntries` reads them back for the downtime and note history endpoints. `0018` copies every row of `equipment.downtime_audit`, `alarms.alarm_transition` and `shifts.handover_audit` into it (`legacy`, counts checked) and freezes the first and the last (no `INSERT` for `mes_app`, a trigger for everyone); `alarms.alarm_transition` stays the alarm module's transition log, an operator transition writes both.
  - **Actors:** with `MES_AUTH=on` every write takes its actor from the session (user, roles, `authenticated: true`) and ignores `codedBy`, `actor` and `author`; with `off` the typed name is used and is required (422 without it). The three fields are optional in the request schemas until #170 removes them.
  - **`shifts.crew_assignment`:** user, work center, shift instance, terminal session, sign-on and end (`0019`); written from #177.
  - **Review of PR #185:** the grants test compares every grantee, PUBLIC included, on schemas, relations, sequences and non-default function ACLs (PUBLIC has nothing); the downtime history filters and limits in SQL; `migrate` leaves exactly one membership (revoking any other by its grantor) and resets connection limit and expiry; the ownership step is tested from 0015 and from 0016 with a #168 row left untouched, and the whole catalog (owners and ACLs of every relation, `_timescaledb_internal` included, functions and schemas) equals a fresh database's; the backfill skips system expiries and epoch ends and keeps each audit's id order; only a SCRAM verifier of `DB_APP_PASSWORD` (printable ASCII) reaches the server; `PUBLIC` loses `CONNECT` and `TEMPORARY` on the database; ADR-0027 and ADR-0022 state the aggregates' accepted cost fully, with a forced full refresh as the recovery in the runbook; a stopped MES no longer starts after the migration wait.
  - **Tests and smoke:** the module tests run as `mes_app` (`freshDatabase` migrates as the superuser and hands out an `mes_app` connection; fault injection uses `ownerOf`); the stack smoke checks that the MES is connected as `mes_app`, that the refusals hold as `mes_app` and as `mes_cagg`, and that a refresh needs `SET ROLE mes_cagg`; the reconciliation checks `identity.audit_log` and `alarms.alarm_transition` for append-only refusals and generates `DB_APP_PASSWORD`. `.env.example` gains the placeholder `DB_APP_PASSWORD=change-me` (and the CI smoke's `.env` a random one).
- Gateway command path for `load-order` (#173; ADR-0029, UNS contract 1.3).
  - **Contract 1.3:** commands `uns.cmd.load-order/1` on `…/cmd/load-order` (command envelope with `issuedAt`, `expiresAt` and `commandId` `{orderId}~OP10~{n}`), results `uns.cmd-res/1` on `…/cmd-res/load-order` (`accepted` and `duplicate` with the device's `position`, `acceptedSeq` and `acceptedAt`; `rejected` with a code; `expired` and `unknown` with `seqAfterExpiry`), both validated by `parseUnsCommandMessage`; job facts `uns.events.job/1` on `…/events/job` among the fact schemas. Helpers `jobTopic`, `commandTopic`, `commandResultTopic`, `loadOrderCommandId`; JSON Schemas in `docs/contracts/uns/`.
  - **Command session:** a second MQTT connection, client id `gw-01-cmd` under the broker user `gw-01`, `clean: false` with `GATEWAY_CMD_SESSION_EXPIRY_S` (default 1 h), subscriptions `cmd/#` per area; a delivery is acknowledged only after it is committed to the gateway's SQLite inbox (a failed insert is never acknowledged and arrives again). Readiness needs both sessions.
  - **Calls:** one command at a time per CNC, only on a ready OPC UA session, each request with `GATEWAY_CALL_DEADLINE_MS` (default 5 s); `ShopFloor.Epoch` re-read before every retry (a changed epoch is `rejected`, `epoch-mismatch`, without a call); retries until `expiresAt`; no gateway-side `expired` shortcut.
  - **Settling:** an outcome without a definitive answer by `expiresAt` is settled after `expiresAt` + 1 s by reading `ShopFloor.Sequence` (`seqAfterExpiry`) and one more call; `Duplicate`, the device's `expired` and `epoch-mismatch` are final, anything else is published as `unknown` and settled again every 5 s. A finished simulator answers the transient status, so its commands stay `unknown` (documented).
  - **Result table:** definitive answers by command id, `expired` by command id and `expiresAt`; redeliveries and resends of the same job are answered without a call; `unknown` is never stored. Results go through the store-and-forward outbox.
  - **Job facts:** `ShopFloorJobEventType` is published on `events/job` in the machine's device sequence.
  - **Broker ACL:** `gw-01` reads `cmd` and writes `cmd-res` per area; `cmd` refused (0x87) for `gw-01` and `dev`, `cmd-res` for `mes` and `dev`, tested.
  - **Metrics:** `gateway_command_deliveries`, `gateway_command_calls`, `gateway_command_results{result}`, `gateway_command_pending{stage}`.
  - **Review of PR #184:** stored answers are keyed by the command's `deviceEpoch` too (an answer of one simulator run never answers another's command; an older table is dropped) and pruned after 24 h; a settle call waits for the device's own clock (`Server_ServerStatus_CurrentTime`) past `expiresAt` + 1 s; a settle call answered as a new acceptance stays `accepted`, logged as clock skew and counted (`gateway_command_settle_acceptances`); the outbox never evicts `cmd-res`; stopping waits for running deliveries; the `seqAfterExpiry` boundary (every accepted fact at most it, re-dispatch once final-through is at or above it) and the precedence of several results per command id are documented.
  - **Tests:** the executor against the simulator in orders mode through TCP proxies that hold answers or cut connections; end to end with Mosquitto and the gateway process (`commands.e2e.test.ts`) for the gateway's cases of Phase 7 exit criterion 3. The MES ingest refuses `events/job` and `cmd-res` until #174.
- MES `identity` module behind `MES_AUTH=off` (#168, ADR-0026; ADR-0019 and ADR-0023 notes; migration `0016`).
  - **Roles and permissions:** `@shopfloor/contracts/identity` defines the five roles (`operator`, `maintenance`, `quality`, `supervisor`, `admin`), fourteen permissions and the matrix `ROLE_PERMISSIONS` of the Phase 7 plan (a test compares it cell by cell); `admin` holds only `read` and `user:admin`. `identity.role`, `identity.user_account` and `identity.user_role` store users with one or more roles.
  - **Passwords:** `node:crypto` scrypt, N = 2^15, r = 8, p = 3, 16-byte salt, stored as `scrypt$N$r$p$salt$hash`, `maxmem: 64 MiB` passed on every call (Node's default refuses these parameters, tested), at most two hashes at a time, rehash at login when the parameters differ; 12–128 characters, no composition rules.
  - **Sessions:** `POST /api/v1/session` sets `sft_session` (32 random bytes; `HttpOnly; SameSite=Strict; Path=/; Max-Age=43200`; `__Host-sft_session` and `Secure` with `MES_COOKIE_SECURE=on`); only its SHA-256 is stored in `identity.session`. Idle 60 min (`desk`) or 15 min (`terminal`), absolute 12 h; `GET /api/v1/session`, `DELETE /api/v1/session`, `POST /api/v1/account/password` (ends the other sessions); a login ends the session it presents.
  - **Failures:** every failed login is the same 401 after one hash (a dummy for an unknown user); five in a row lock a normal account for 15 minutes; an admin is delayed instead (1 s after the fifth failure, doubling, at most 5 min). Every login, failure, lock, logout and user change is a row of the append-only `identity.audit_log`.
  - **Users:** `GET /api/v1/users`, `POST /api/v1/users`, `PUT /api/v1/users/{username}` (roles, enabled; disabling ends the user's sessions and closes its sockets; the last enabled admin stays one), `POST /api/v1/users/{username}/password` (temporary password, clears a lock), all `user:admin`. A temporary password allows only the session and password routes (403 `urn:shopfloor:password-change-required`) until changed.
  - **Bootstrap and CLI:** optional `MES_BOOTSTRAP_ADMIN_PASSWORD` creates the user `admin` (must change its password) when no enabled admin exists; without it the MES starts with a warning. `pnpm --filter @shopfloor/mes-server user:create --username <name> --role <role>… [--must-change]` reads the password from stdin.
  - **Enforcement (`MES_AUTH=on`):** every route declares its access (a permission, `session` or `public`); after the Host, `MES_WRITES`, Origin, `Sec-Fetch-Site` and JSON guards come 401 `urn:shopfloor:unauthenticated`, 403 `urn:shopfloor:forbidden`, then the global and a new per-user write bucket (5/s, bursts of 10). The WebSocket closes a socket without a session, or whose session ends or expires, with 4401. `/health/*` and `/metrics` stay open. New problem types also `urn:shopfloor:password-rejected` and `urn:shopfloor:user-exists`. The OpenAPI document names each route's access and lists 401 and 403.
  - **`MES_AUTH=off`** (the default here and in Compose until #170): everything but the session routes behaves as before, so the web, the end-to-end tests, the stack smoke and the reconciliation need no login; the MES logs a warning at start.
  - **Review of PR #182:** an `Upgrade` header without a real WebSocket upgrade no longer skips the guards and authentication (only `@fastify/websocket`'s upgrade of `GET /api/v1/ws` takes the WebSocket branch); every login attempt is reserved in a locked-row transaction before its hash, so parallel attempts can't outrun the lockout or the admin delay, and a wrong current password counts the same way; logins have buckets of their own (per user name and all together, 429 `urn:shopfloor:login-rate`) instead of the write bucket; `MES_WRITES=off` exempts login, logout and the password change; a WebSocket whose session must change its password or lacks `read` closes with 4403; logout clears the cookie also for an ended or invalid session; unknown names are logged and audited as `(unknown)`; the dummy hash is made at start; password length is counted in code points by schema and policy alike; indexes for the session sweep.
  - **Tests:** the module (hashing, lockout, admin delay, idle and absolute expiry, logout, password change, disabling, bootstrap, rehash, append-only audit), a route matrix over all 46 routes of the OpenAPI document for anonymous and each role, cookies, guard order, the WebSocket's 4401 on no session, logout, disabling and expiry, the per-user bucket, `MES_AUTH=off`, no password or token in the captured logs, the CLI as a process, and `.env.example` holding only placeholders (`MES_BOOTSTRAP_ADMIN_PASSWORD=` added).

It reads, through the other modules' `index.ts`, the hourly state rows and the Stopped pieces with their whole interval's length in one REPEATABLE READ snapshot (`Equipment.oeeInputs`; the Stopped time is derived from those pieces), and the cycles from `cycle_hourly`. Per equipment and per work center (sums of the machines' inputs), per UTC hour and per shift bucket (the hours grouped by shift), per device epoch (newest by default). A bucket is `final` when every hour is final in equipment, both aggregates are refreshed through it, no open stop is still below the threshold and every member is complete; it carries `provisionalMs`, `revision` and `incidents`. An open stop's whole length runs to the later of the machine's "final through" and its stored end.
  - **REST under `/api/v1`.** `GET /oee`, `/shifts/{date}/{shift}/oee`, `/shifts`, `/shifts/current`, `/reason-codes`, `/downtime` and `/downtime/pareto`, zod-validated with bounded ranges and problem details; response schemas in `@shopfloor/contracts/mes-api` (results in the ground truth's JSON shape); OpenAPI regenerated.
  - **WebSocket.** Topic `oee:<equipment or work center>` (snapshot, then at most one delta per topic per second, computed off ingest's path) and `downtime` (records created, closed, recoded, updated, removed, from a debounced read after each `piecesChanged`); per-client limit of 16 OEE topics; `docs/api/realtime.md` and the message schema regenerated.
  - **Golden-week OEE reconciliation** (exit criterion 2): for every machine and both work centers in every shift bucket of the golden week, the MES's OEE equals the ground truth exactly (inputs, fractions, four-decimal strings, totals, losses, `unplanned`), in order and shuffled with 10 % duplicates, with no incident or revision; scheduled buckets are final, the no-shift bucket's OEE is null on both sides. Σ hours = shift for the OEE totals, the stop pieces per hour equal the ground truth's, and each shift's downtime Pareto equals its availability and micro-stop losses.
  - **Live reconciliation.** `pnpm test:reconcile` also requires shift A's `GET /api/v1/shifts/2026-10-12/A/oee` final for all six machines and equal to the live ground truth's OEE exactly, per machine and work center.

- Hourly continuous aggregates for OEE (#118, ADR-0022; migration `0006`): `equipment.state_hourly` (time and provisional time per state per equipment, epoch, UTC hour and shift bucket) and `ingest.cycle_hourly` (cycles per equipment, epoch, UTC hour, product and result), real-time, no refresh policies. Each owning module refreshes its aggregate explicitly through a shared helper (`AggregateRefresher`): every write below the watermark marks its hour dirty, a debounced (1 s) refresh off ingest's acknowledgement path covers `[earliest dirty hour, latest final hour + 1 h)` on its own connection, and a catch-up refresh runs at start-up. Equipment emits `piecesChanged`; ingest sends `cycle` and `epoch` notices. `Equipment.stateHourly` (with `final` and `revision`) and `Ingest.cycleHourly`/`cyclesRefreshed` are the read side for #120. `equipment.bucket_finality.cycles` remembers each final hour's cycle count; start-up compares it with `cycle_hourly` and revises an hour whose count changed unheard (the #113 proposal). The data-model generator documents views and continuous aggregates (definition, bucket, `materialized_only`), with drift tests.
- Reason codes, auto-classification and downtime records (#119, ADR-0021 amended).
  - **Cause vocabulary.** All causes are defined in `@shopfloor/contracts`: `CAUSES`, `materialCause`, `changeoverCause`, `NO_PRODUCT` and `causeVocabulary`. The simulator and the Modbus cause table use it. The golden week is byte-identical.
  - **Reason tree and rules.** `config/plant/reasons.yaml` holds the reason tree (ids are paths such as `BREAKDOWN/SPINDLE-OVERLOAD`) and an ordered list of rules from (state, cause pattern: exact, `{prefix}`, `null` or `{any}`) to a reason. The first match wins, and no match gives UNCODED.
  - **plant-config.** `plant-config` loads `reasons.yaml` outside the simulator's config hash and exports `classifyCause`. Its cross-check refuses:
    - unknown reasons;
    - parents not listed before their children;
    - a missing UNCODED;
    - loss states without a `null` fallback;
    - any cause of the plant model left UNCODED.
  - **Reason codes in master data.** Migration `0007_master_data_reason_codes.sql` adds `master_data.reason_code`. A reason the configuration drops stays, marked inactive. `MasterData.reasonCodes()` lists the tree.
  - **Downtime records.** Migration `0008_equipment_downtime_records.sql` adds `equipment.downtime_record` and `interval_source.downtime_threshold_ms`.
    - There is one record per availability-loss interval per scheduled shift bucket, keyed by its start in the bucket.
    - A Stopped interval makes a record from the micro-stop threshold on. Micro-stops, planned states and `no-shift` make none.
    - Records are stored in the same statement as the pieces on every interval path, and their `provisional` flag follows the pieces' finality.
    - Catch-up derives the records again when the threshold changed. Start-up recodes the records whose reason changed with the rules.
  - **Interface for #120.** `Equipment.downtimeRecords()` returns the records, with an UNCODED-first order. `availabilityLoss` is in `oee-core`.
  - **Tests.** A simulator test checks that every (state, cause) pair of the golden week is in the vocabulary and none is UNCODED. The golden-week reconciliation checks that every availability-loss interval has its records, that none is UNCODED, and that shuffled delivery stores the same records. `docs/data-model.md` is regenerated, and `docs/simulation-model.md` gains a "Causes" section.
- Simulator ground-truth OEE with `oee-core` (#117): `GroundTruth` keeps, per machine, the OEE inputs of every shift bucket and every UTC hour (time per state; Stopped intervals held until they close, then filed as pieces with their whole length; cycles per product and result, bucketed by their time with `shiftKeyAt`), and returns `bucketOee` per machine and shift bucket and `workCenterOee` for Cell M1 and Line A1, with fractions as `num/den` and four-decimal strings, losses, `unplanned`, `anomaly` and `provisional`. An open stop's whole length runs to the snapshot time (ADR-0021). Summary format `sim-summary/2` (new `oee` section; all other fields unchanged). Golden `week-01/summary.json` regenerated for the new section only (39,404 lines added; the schema line is the only changed line); `events.sha256` unchanged (`e7c69736…009b740b`), so the simulation itself is unchanged. A snapshot costs about 0.2 ms after a shift and about 3 ms after a week (response about 450 KB after a week).
