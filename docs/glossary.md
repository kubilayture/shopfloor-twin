# Glossary

Industrial and project terms used in code and docs, in alphabetical order. Each points to the record that defines it exactly; when a definition here and its source disagree, the source wins. Seeded from master plan section 13, which now points here; add a row whenever a new term appears in code or docs (master plan section 10).

| Term                               | Meaning in this project                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ADR                                | Architecture Decision Record: a short file recording one decision, its options and consequences ([`docs/adr/`](adr/README.md), ADR-0001)                                                                                                                                                                                                                                                                                                                                                                                          |
| Alarm flood                        | More than `floodThreshold` (10) alarm raises in a 10-minute window (ISA-18.2, EEMUA 191). Counted two ways: fixed 10-minute windows aligned on the hour (`floodWindows`, `peak10`) and sliding **flood episodes**, which start at the raise that exceeds the threshold and end when the count is back at it; a position's open episodes are its flood banner (ADR-0024, `config/plant/alarms.yaml`)                                                                                                                               |
| Alarm KPIs                         | ISA-18.2 measures per operator position, equipment or the plant, per UTC hour and shift bucket: raises (every device `active` transition, shelved or not), average and peak rate per 10 minutes, floods, chattering, fleeting and standing alarms, bad actors; exact and reconciled with the ground truth. Time to acknowledge and shelving are reported beside them, not reconciled (ADR-0024)                                                                                                                                   |
| Alarm occurrence                   | One raise of an alarm on a device and what followed it: keyed `{equipment}~{epoch}~{seq}`, ended by the device's clear, `superseded` by the next raise, `lost` in a resync or `epoch-ended`; the operator adds acknowledgement and comments (ADR-0010, `docs/api/realtime.md`)                                                                                                                                                                                                                                                    |
| Anchor                             | A retained UNS delivery (state, or an alarm's last fact) that restores current state when a consumer subscribes without entering the device stream: it neither starts the stream nor makes a gap. It carries its device epoch (`deviceEpoch`); the first anchor per (equipment, device epoch) wins, and it opens the first interval only if it is earlier than the first fact (ADR-0017, ADR-0018)                                                                                                                                |
| Availability, Performance, Quality | The three OEE factors per equipment, device epoch and bucket: **A** = actual production time ÷ planned busy time; **P** = ideal time ÷ actual production time, not capped (P > 1 is possible at hour granularity); **Q** = good ÷ produced. Exact fractions, never floating point (ADR-0021, [`oee-reference-cases.md`](oee-reference-cases.md))                                                                                                                                                                                  |
| Blocked / Starved                  | A machine that cannot unload because the downstream buffer is full / cannot load because the upstream buffer is empty. Availability loss, but **external** (not the machine's fault); a starved station names its cause, e.g. `MATERIAL:<material>` for a blocked lot (ADR-0021, [`simulation-model.md`](simulation-model.md))                                                                                                                                                                                                    |
| Bottleneck (designed)              | Per product, the routing operation with the largest **effective cycle**: its ideal cycle ÷ the number of machines that run it, ties to the earlier operation. Derived by `oee-core` (`deriveBottlenecks`), never configured: ASM-01 (OP30) for both products, although OP10 has the largest raw cycle, because two CNCs share OP10. It holds whatever the plant does (ADR-0036)                                                                                                                                                   |
| Carton                             | A packing unit of good units of one order and product, formed by the MES with the packing rule shared with the ground truth (`trace-core`'s `packCartons`; capacity per product in `config/plant/packing.yaml`). It closes when full, or at the order's completion (a short order has a partial carton); id `{orderId}-C{nn}`. "Shipped" means packed in a closed carton (ADR-0034)                                                                                                                                               |
| Changeover (setup)                 | Time to switch a machine from one product variant to another; state `Setup`. In orders mode it counts against the order that caused it, because the order's window starts at its head time (ADR-0036)                                                                                                                                                                                                                                                                                                                             |
| Characteristic                     | A measured quality property charted by SPC; in v1 the leak test's leak rate on LKT-01 (OP40), read as integer counts of the instrument's resolution (0.001 Pa/min). Only first-pass readings are charted (ADR-0032, `config/plant/quality.yaml`)                                                                                                                                                                                                                                                                                  |
| Command envelope                   | The UNS message that carries a command from the MES (`uns.cmd.load-order/1` on `…/cmd/load-order`): `issuedAt`, `expiresAt` (a command not accepted by then is refused) and a `value` with `commandId` (`{orderId}~OP10~{n}`, reused by resends), the order, product, quantity, `notBefore` and the target `deviceEpoch`. A command is not a fact: no `sourceTime` or `quality` (ADR-0029, [`contracts/uns.md`](contracts/uns.md))                                                                                                |
| Confirmation                       | The MES's report to the ERP of an order operation's yield, scrap per reason, rework passes and backflushed material: one final confirmation (number 1) once the operation is complete, then corrections (2, 3, …) with signed deltas when its totals later differ; idempotent by `{order}~{operation}~conf~{n}` (ADR-0028, ADR-0031, [`api/erp-mock.md`](api/erp-mock.md))                                                                                                                                                        |
| DES                                | Discrete-event simulation: time jumps from event to event instead of ticking (ADR-0006)                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Dev CA                             | The stack's own certificate authority, made by the `pki` step: it issues nginx's certificate for the HTTPS front (`https://localhost:8443`). Per stack, name-constrained to `localhost` and `127.0.0.1`, `serverAuth` only; a browser shows a warning until it is trusted (`pnpm stack:ca`). Separate from OPC UA trust (ADR-0039)                                                                                                                                                                                                |
| Device epoch                       | The start time (Unix seconds) of the simulator run that owns a device sequence, exposed as `ShopFloor.Epoch` (OPC UA) and two Modbus registers. A larger epoch starts the stream over (a restart); a smaller one is old. Intervals, finality, units and shift instances are kept per epoch (ADR-0015)                                                                                                                                                                                                                             |
| Dispatch                           | A supervisor's action in the MES that sends a released order's job to a CNC: a `LoadOrder` command on the UNS, executed by the gateway as an idempotent OPC UA method call; the device's `accepted` job fact confirms it (ADR-0029, ADR-0030)                                                                                                                                                                                                                                                                                     |
| DMC                                | Data Matrix Code laser-marked on a part, carrying its serial number                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Dynamic security (dynsec)          | Mosquitto's dynamic-security plugin, which replaced the ACL file in Phase 9: users with roles and ACLs, each user bound to one client id, generated per stack from `config/mosquitto/dynamic-security.json` with the passwords of `.env`; anonymous clients refused (ADR-0039, [`contracts/uns.md`](contracts/uns.md) "Broker")                                                                                                                                                                                                   |
| Final, provisional, final through  | **Final through** is, per (equipment, device epoch), the latest source time of a device fact with no open sequence gap at or below it. A piece of data (an interval piece, an hour, an OEE or KPI bucket, a shift report, an order's OEE, a trace answer) is **final** once it lies before final through, so no fact that can still arrive may change it; until then it is **provisional**. A change to a final bucket raises its **revision** (ADR-0018 amendment, ADR-0025, ADR-0034)                                           |
| First-pass yield                   | Two uses: at a machine, OEE's Q = good ÷ produced, where a leak-test rework is produced but not good (ADR-0021); across the routing, `firstPassYield` = units packed good with every record good (no rework, no retest) ÷ units started, reported beside an order's OEE and never multiplied in (ADR-0036)                                                                                                                                                                                                                        |
| Gap incident, write-off            | A **sequence gap** is a hole in a device's sequence numbers. Open for `INGEST_GAP_GRACE_MS` (30 s), it becomes a `sequence-gap` incident (data loss made visible); a late message still fills it (`filled`) and a newer epoch ends it (`epoch-ended`). Writing a gap **off** records it as `reported` so finality may pass it; numbers below the first one seen (history the MES joined late) are written off without an incident. Data over a written-off gap carries `incidents` and `mayRevise` (ADR-0015, ADR-0017, ADR-0018) |
| Gate (merge gate)                  | `pnpm gate`: the local equivalent of every CI job (`verify`, `golden`, `e2e`, the stack smoke, `reconcile`) on the checked-out commit, on a disposable Compose project, ending with one record; it has replaced green CI as the merge condition since PR #149 while GitHub Actions is unavailable (runbook "Merge gate", ADR-0011 note)                                                                                                                                                                                           |
| Genealogy                          | Parent-child links between lots, units (serials) and cartons that make traceability possible: rebuilt from cycle facts (lots consumed, operator) and the packing rule; a serial traces back to its lots, machines, operators and tests, a lot forward to its cartons (ADR-0033, ADR-0034)                                                                                                                                                                                                                                         |
| Golden scenario                    | A fixed seed and scenario whose expected outputs (`events.sha256`, `summary.json`, `trace.json`, `line-oee.json`) are committed under `apps/simulator/golden/` and checked byte for byte by `pnpm test:golden` in every gate; a regeneration needs the owner's approval (master plan section 9)                                                                                                                                                                                                                                   |
| Ground truth                       | What the simulator knows happened, written by its headless run beside the event log (`summary.json`, `trace.json`, `line-oee.json`) or read live through the control API: the reference the MES's answers are reconciled with. It is computed with the same pure packages (`oee-core`, `alarm-core`, `spc-core`, `trace-core`) and knows no operator action ([`simulation-model.md`](simulation-model.md))                                                                                                                        |
| Head time, job window              | A job's **head time** is when it becomes the head of its CNC's queue: `max(accepted fact, previous job's completion, notBefore)`. Its **job window** runs from the head time to its completion, so the changeover counts against it; an order's OEE is computed over its jobs' windows (ADR-0036 and its P9-03 amendment)                                                                                                                                                                                                         |
| Heavy lock                         | A host-wide lock (`~/.cache/shopfloor-twin/heavy.lock`) that every heavy command takes first (`pnpm gate`, `verify`, `test:e2e`, `test:reconcile`, Playwright, …), so one heavy suite runs at a time; holding it, a command refuses to start below 25 GiB free on the host or 15 GiB in Docker (runbook "Merge gate")                                                                                                                                                                                                             |
| Hold, hold scope, close guard      | A **quality hold** is opened by a quality user on a lot, a serial, a carton or an order and ends `released` (use as is) or `rejected`. Its **scope** is never listed by hand: it is derived from the genealogy (every unit the subject covers now, so it grows with facts). The **close guard** refuses an order's close while a hold's scope covers it, deriving the scope under one advisory lock shared with hold opening (ADR-0035)                                                                                           |
| I-MR and X̄-R charts                | The SPC charts: **I-MR** charts individual readings and their moving ranges; **X̄-R** charts the means and ranges of consecutive subgroups of n (5). Limits from Shewhart constants (E2, D4, A2, D3) (ADR-0032, [`spc-reference-cases.md`](spc-reference-cases.md))                                                                                                                                                                                                                                                                |
| Idempotency key                    | A key built from a message's content so that a repeated delivery is recognised: the ERP mock's `Idempotency-Key` (`confirmationKey`, `statusKey`, `qualityNotificationKey`) and a command's `commandId`; a repeat with the same body gets the original answer, another body under the key is a conflict (ADR-0028, ADR-0029)                                                                                                                                                                                                      |
| ISA-95                             | Standard for integrating enterprise and control systems; defines the equipment hierarchy and the level model used here                                                                                                                                                                                                                                                                                                                                                                                                            |
| ISO 22400-2                        | Standard defining manufacturing KPIs, including the OEE terms used here                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Job, job facts                     | One order's work on one CNC, created by `LoadOrder` and run FIFO from the CNC's queue. **Job facts** are device facts in the CNC's sequence: `accepted`, `started` (the first blank taken, after any changeover) and `completed` (the end of its last OP10 cycle); they are the proof of execution. A unit's OP10 cycle belongs to the job whose `started` fact is the latest before it (ADR-0030, ADR-0031)                                                                                                                      |
| Limit version, baseline            | SPC control limits are frozen in versions. **Version 1** is estimated from the first 20 complete subgroups, the **baseline**, created at the baseline's last reading and never re-derived; points are judged against the version that applies to them (ADR-0032)                                                                                                                                                                                                                                                                  |
| Line (throughput) OEE              | Σ good packed units × the bottleneck's effective cycle per product ÷ line planned busy time, per hour, shift bucket or order: one ratio, no A × P × Q split. In orders mode the line's planned time counts only while an order is in progress. Not capped: above 1 is flagged `aboveOne` (ADR-0036)                                                                                                                                                                                                                               |
| Lot                                | A material lot (blanks, components, seal kits) from the ERP's lot list, which defaults to `config/plant/stock.yaml`, the file the simulator stocks from. Cycle facts name the lots consumed for the part, so genealogy links lots to units; a lot can be blocked in the plant (a timeline action) or held in the MES (ADR-0028, ADR-0033, ADR-0034)                                                                                                                                                                               |
| MES                                | Manufacturing Execution System: software that manages and records production on the shop floor                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Micro-stop                         | A `Stopped` interval whose whole length is below the threshold (120 000 ms); counted as performance loss, not availability loss. Breakdowns (`Down`) are never micro-stops (ADR-0021)                                                                                                                                                                                                                                                                                                                                             |
| Modbus TCP                         | Older, register-based industrial protocol with no built-in semantics; WSH-01's interface ([`contracts/modbus-register-map.md`](contracts/modbus-register-map.md), ADR-0013)                                                                                                                                                                                                                                                                                                                                                       |
| MQTT                               | Lightweight publish/subscribe protocol; QoS 1 means at-least-once delivery                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Nelson rules                       | Run rules that flag a non-random pattern on a control chart (1: a point beyond a limit; 2: nine on one side; 3: six rising or falling; … 8). Rules 1, 2 and 5 are on by default on I and X̄, rule 1 on R. Consecutive points where a rule fires form one **signal episode**, acknowledged once (ADR-0032)                                                                                                                                                                                                                          |
| `NO-ORDER`                         | The cause of an `Idle` CNC whose queue has no startable job in orders mode (`PLANNED/NO-ORDER`). Excluded from planned busy time under `scheduledTime: orders`, like a planned stop (ADR-0030, ADR-0021 amendment)                                                                                                                                                                                                                                                                                                                |
| `NotBefore`                        | A dispatched job's earliest start in plant time (`notBefore` in the command, `NotBefore` of `LoadOrder`): the head of the queue waits for it, and it is part of the head time; a dataset's `plannedStart` becomes it (ADR-0030, ADR-0036 P9-03 amendment)                                                                                                                                                                                                                                                                         |
| OEE                                | Overall Equipment Effectiveness = Availability × Performance × Quality = (ideal time × good) ÷ (planned busy time × produced), one exact fraction. Per equipment and work center (ADR-0021), per order over its job windows, and as line throughput OEE (ADR-0036)                                                                                                                                                                                                                                                                |
| OPC UA                             | Industrial communication standard with a typed information model, subscriptions, methods and security; the five machining and assembly machines' interface ([`contracts/opcua-address-space.md`](contracts/opcua-address-space.md), ADR-0008, ADR-0009)                                                                                                                                                                                                                                                                           |
| Operator position                  | A set of work centers one operator watches, the scope of alarm KPIs and flood banners (`positions` in `config/plant/alarms.yaml`; `alarm-kpi:position:<id>`) (ADR-0024)                                                                                                                                                                                                                                                                                                                                                           |
| Pinned certificate (PKI pinning)   | OPC UA trust without a CA: each server trusts exactly the gateway's and the tools client's self-signed leaf certificates, and the clients exactly the five servers', copied into `trusted/certs` by the `pki` step; nothing else opens a session (ADR-0038)                                                                                                                                                                                                                                                                       |
| `pki` step                         | The one-shot Compose service that runs before the simulator, gateway and web on every `up`: it makes or renews the OPC UA keys, certificates and pins and the dev CA with nginx's certificate, in volumes only it mounts together (ADR-0038, ADR-0039)                                                                                                                                                                                                                                                                            |
| Plant clock, watermark             | The **watermark** of a device epoch is the latest source time of any device fact, or of a telemetry sample naming that epoch: how far the plant is known to have run. The **plant clock** is the newest epoch's watermark; live OEE, alarm KPI and shift topics follow it (ADR-0018)                                                                                                                                                                                                                                              |
| Planned busy time                  | The time OEE plans: every state except `PlannedStop`, `Maintenance` and `Off` inside a scheduled shift (and, in orders mode, except Idle `NO-ORDER`); the denominator of availability (ADR-0021)                                                                                                                                                                                                                                                                                                                                  |
| Production mode                    | How the simulator decides what OP10 makes: `schedule` (the weekly schedule file, Phases 1–6, the dev stack's default) or `orders` (only jobs dispatched by the MES through `LoadOrder`; `SIM_PRODUCTION=orders`) (ADR-0030)                                                                                                                                                                                                                                                                                                       |
| Reconciliation                     | Comparing the MES's answers with the simulator's ground truth for the same run, exactly: headless in the golden e2e tests and live in `pnpm test:reconcile` (passes `alarms`, `orders`, `quality`) (runbook "Reconciliation run")                                                                                                                                                                                                                                                                                                 |
| Rework                             | A unit that fails its first leak test (result `rework`, reason `LEAK`) goes back to OP30 through a separate rework queue and is tested again (pass 2); a second failure is scrap. Rework consumes the product's `reworkComponents` ([`simulation-model.md`](simulation-model.md) "Rework loop", ADR-0031)                                                                                                                                                                                                                         |
| Shelving                           | An operator's suppression of an alarm point for a limited time (at most `maxShelveMs`, 8 hours): its occurrences leave the active list but keep their states; the shelf ends when unshelved, when it expires or at a new device epoch. Never on the device and never reconciled (ADR-0010, ADR-0024)                                                                                                                                                                                                                              |
| Shift instance, report finality    | A shift on one date (`2026-10-12/A`), recorded per plant epoch when the plant clock enters it, with status `running` → `ended` → `final`; its report is final once every input is final, and a composite revision moves when an input or a handover note changes after that. Time outside shifts is a `no-shift/{start}` bucket (ADR-0025)                                                                                                                                                                                        |
| SignAndEncrypt                     | The OPC UA security mode in which every message is signed and encrypted; the only endpoint the five servers offer (`Basic256Sha256`, `Aes128_Sha256_RsaOaep`), with user-name tokens for the users `opcua-gateway` and `opcua-reader` (ADR-0038)                                                                                                                                                                                                                                                                                  |
| Simulation time, speed             | The plant's own clock as integer milliseconds, independent of wall time; the live simulator runs it at a speed factor (`SIM_SPEED`, 60× on the dev stack, so a shift lasts 8 minutes); headless runs as fast as it can (ADR-0006)                                                                                                                                                                                                                                                                                                 |
| SPC                                | Statistical Process Control: control charts and run rules that detect process drift; here I-MR and X̄-R charts with Nelson rules on the leak test (ADR-0032)                                                                                                                                                                                                                                                                                                                                                                       |
| Store-and-forward                  | Buffering data locally while the network is down and sending it later in order: the gateway's SQLite outbox (ADR-0014)                                                                                                                                                                                                                                                                                                                                                                                                            |
| Timeline                           | A scenario file (`config/scenarios/<name>.yaml`) of plant actions at fixed simulated times (failures, leak drift, lot block and release, absences, tool breakage, dispatches) that plays back identically headless and live; `demo-v1` is the demo's (ADR-0037 and its amendments, [`simulation-model.md`](simulation-model.md) "Scenario timelines")                                                                                                                                                                             |
| UNS                                | Unified Namespace: one shared MQTT topic tree, organized by the plant hierarchy (`orbis/gebze/{area}/{workcenter}/{equipment}/{class}/{name}`), as the single hub of shop-floor data; every message in one versioned JSON envelope ([`contracts/uns.md`](contracts/uns.md), ADR-0015)                                                                                                                                                                                                                                             |
| Unit, serial                       | A **unit** is one part, keyed (device epoch, `partId`); its **serial** is the DMC marked at OP10. Serials repeat across simulator runs, so a lookup by serial lists every unit with it, newest epoch first (ADR-0031, ADR-0034)                                                                                                                                                                                                                                                                                                   |
