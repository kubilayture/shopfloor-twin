## Review findings that mattered

Every pull request had an independent review (ADR-0011). The findings below changed the design or caught a defect before merge. As in Phase 5, most were found because a reviewer _ran_ something: a probe against Testcontainers, a Python recompute, a fuzz of thousands of orderings, a throwaway stack, fake pages built to fool a judge.

- **Plan (#138, PR #149), four blockers in round 1, fixed before any code:**
  - **Injection broke the line model.** Injecting a failure in Stopped, Starved or Blocked hit paths that assume a running machine. Now an injection applies only in `Running` and is held otherwise, with `failure` guards and per-state invariant tests.
  - **Windowed KPIs and per-hour revisions.** Revising only the late fact's own hour missed flood, peak and chattering changes in later hours. Now a late fact revises [t, t + max window] plus the raise→clear span.
  - **Flood finality.** An open flood episode would have kept every bucket it touched provisional. Now each bucket reports its clipped `floodMs`, the peak so far and `open`, which are final with the bucket.
  - **Phantom anchors.** A retained alarm of an old epoch would have opened a standing alarm after a simulator restart. Old-epoch anchors are ignored.

  Round 1 also brought the resync alarm snapshot for lost clears; round 2 fixed the snapshot's identity, the composite report revision and the "no zero-length Running" rule.

- **`alarm-core` (#139, PR #150):** a raise arriving exactly when a flood ended was counted in it (episodes are now [start, end), case 21); raises of two devices in one millisecond were ordered by `seq`, which only orders one device's events, so flood ids could differ between the simulator and the MES (now ordered by equipment, ids without `seq`, case 22). The reviewer's 30,000-case revision fuzz became a property test.
- **Ingest and gateway (#141, PR #152), blocking: lost washer facts.** On Modbus, an event lost to a ring overrun or an undecodable entry did not trigger a snapshot, so a lost clear kept WSH-01's occurrence open for good, exactly what the snapshot exists to prevent. It now triggers one; the snapshot is published after the ring loop, and consumers apply it only once `settledSeq ≥ asOfSeq`.
- **`alarms` module (#142, PR #153), two blocking false revisions** (the class of #129 and #133 in Phase 5), reproduced by probes:
  - **P1:** when a finality jump made a waiting snapshot applicable, revisions were judged against the new frontier, and hours never reported final got revision 1;
  - **P3:** at start-up, catch-up overwrote the stored frontiers before judging revisions, so an epoch closed while the MES was down made every hour count as final.

  Both now judge against what was final before the change; P1 and P3 are regression tests. The re-review closed two narrow reader windows: a new "final through" and an epoch's close are published only after the derivation commits, and a failed write keeps the old bounds.

- **Alarm writes (#143, PR #154): bulk acknowledgement deadlock.** Probe A raced a bulk acknowledgement against an occurrence rebuild that updated a higher `seq` and then deleted a lower one; the acknowledgement failed with a 500 (SQLSTATE 40P01). The rebuild now locks its changed rows `FOR UPDATE` in `seq` order, and acknowledgements and comments retry on 40P01 and 40001. The low findings became #156.
- **`shifts` module (#144, PR #155):**
  - **Major, evaluation load:** every alarm finality move (nearly every fact) re-evaluated every report of the epoch, final ones included. Now only reports not yet final are marked, final ones only on an input change in their range, and start-up evaluates only reports not final (a test counts the evaluations).
  - **Medium, read order:** the report read its content before the input revisions, so a revision could lead its content. Now instance row, then revisions, then content: a revision may lag, never lead.
- **Web alarms (#145, PR #158):**
  - **Blocking, ghost alarms (B1):** pushed copies outlived the screen. The `alarms` topic has no snapshot, so after leaving and returning, alarms acknowledged elsewhere still showed as active and bulk acknowledgement couldn't clear them. The pushed set is now reset and the lists re-read on subscribe and release.
  - **Major, drafts across alarms (M1):** the occurrence panel kept its drafts, so a comment typed for one alarm could be posted to another. The panel is keyed by occurrence.
- **Web shift report (#146, PR #162), medium: the M1 lesson again.** A new-note draft followed a switch to another cached shift, so **Add note** would have posted it there. The report body is keyed by `epoch~key`; the test also caught a picker that navigated to `/shifts//`.
- **End to end (#147, PR #165):**
  - **Medium, the audit check could never fail.** psql's output went to `JSON.parse`, so an accepted `UPDATE 17` threw and counted as a refusal, as would a missing trigger. Each statement now runs inside `BEGIN … ROLLBACK`, and only the trigger's own `append-only (UPDATE|DELETE refused)` message counts.
  - **The latency judge's "seen anywhere in the run".** A brief real OEE value whose four decimals the polls had seen at any earlier moment was taken for a stale one, which made the OEE check fail when it sampled later in the shift. `seenWithin` (±5 s) fixes it; unit tests keep pages lagging 2.5 s and 4.5 s failing, an 8-s lag failing snapshot agreement and a frozen page failing.
  - Guards against vacuous passes: exactly 14 injections, the posted `repairMs`, the golden hour sets, a non-empty Pareto.

The reviews of #140 (PR #151), #156 (PR #157), #159 (PR #161) and #160/#163 (PR #164) approved with nothing blocking; their fixes are in the phase log.

## Known issues and carry-overs

- **GitHub Actions is disabled by the spending limit.** CI is configured but cannot start; merges are gated locally (above). Until it runs again there is no CI evidence anyone else can open, and the `reconcile` job's runtime with cold builds is not re-measured.
- **The smoke's audit rows from Phase 5 are still there.** The two `equipment.downtime_audit` rows that #121's first local smoke wrote into the owner's default dev database stay until `pnpm stack:reset` (Phase 5 report). No Phase 6 check wrote into that database: every stack smoke, browser check and reconcile used a disposable Compose project.
- **Audit triggers bind the MES's connection, not the table owner.** Phase 6 adds `alarms.alarm_transition`, `alarms.occurrence_state`, `shifts.handover_note` and `shifts.handover_audit` to the tables protected only by triggers. The MES connects as their owner, which can `ALTER TABLE … DISABLE TRIGGER`. Separate roles come with identity and hardening (Phases 7 and 9).
- **Writes are unauthenticated** until identity (Phase 7): `actor` and `author` are free text, audited with `authenticated: false`.
- **One global write rate limit** (10/s, bursts of 20), now shared by coding, alarm and note writes. A bulk acknowledgement of 100 ids is one token. A per-client limit means nothing behind nginx.
- **`prom-client` is deprecated** upstream in favour of `@prometheus-io/client` (ADR-0012); still open, and Phase 6 added two metric families on it.
- **Retention and compression:** still no policies. A policy must now also respect the alarm tables (`alarm_occurrence` is derived from ingest's facts and `occurrence_source`), `kpi_revision`, the operator tables and both new append-only audits, besides the Phase 5 constraints.
- **KPI read cost:** computing a range is O(hours × occurrences) in `alarm-core` (every hour filters the whole prepared set; a 31-day range is 744 hours), and a read looks back at least two hours, more during a long flood. Fine at this plant's rates; bucketing occurrences by hour once would bound it (ADR-0024 follow-up).
- **The latency judge's known limits:**
  - "seen" means the API's polls held the value within ±5 s of the sample (`seenWithin`); the unseen share (`maxUnobserved`) is still counted over the whole run;
  - a page lagging more than the window passes most latency judgements and is caught only by the snapshot agreement;
  - the flood banner (2 changes) and the KPI cards (28) are judged on small samples per run;
  - the judgement depends on 100-ms polls and on the paced push; a slower machine could move results near the 2-s limit.
- **Open from the log and the ADRs:**
  - an acknowledgement of an occurrence a rebuild later deletes stays as an orphaned row (harmless);
  - shelf expiry follows ingest's notices: with no facts the plant clock and the shelf stand still (by design);
  - an alarm KPI hour without activity is not listed, so its revision isn't seen by the report (a late fact that changes an hour makes it active);
  - the `content` step for an acknowledgement made in a later epoch is conservative (counted, though no figure moves);
  - the `0015` backfill compared two clocks for reports already final; new reports are exact;
  - a re-cut that moves a loss interval still orphans part of a coding (Phase 5);
  - the closed handover window was not reached in a browser (tests cover it);
  - Vite's 500 KB chunk warning (Phase 5) remains.
- **Carried from Phase 4 and 5:** one transaction per message in ingest; client-id takeover on the broker (Phase 9); broker persistence only up to the last autosave; aggregate dirty hours in memory; work-center OEE time-weighted, not throughput-based.
- **Phase 7 (orders, ERP and execution) inherits:**

## Lessons

- **The plan review is the cheapest place for a blocker.** Four blockers (injection outside `Running`, windowed revisions, flood finality, phantom anchors) were fixed in text before any code. Each would have cost a module's redesign later.
- **"Judge against what was final before the change" is now a rule, not a fix.** P1 and P3 were the same class of bug as #129 and #133 in Phase 5: a bound read after something moved it. Capture the old bound first, write revisions in the same transaction, publish the new bound only after the derivation commits.
- **Lock ordering has to hold across code paths, not only within one.** Sorting the keys of bulk acknowledgements prevented deadlocks among them, but not against a rebuild that locked the same rows in another order. Every writer of a table must take its row locks in one global order, and a deadlock-prone transaction should retry.
- **Client state must die with its context.** Three web findings (ghost alarms, a comment draft across alarms, a note draft across shifts) were state that outlived the thing it belonged to. Keying a component by the identity of what it edits, and resetting pushed copies when a topic without snapshots is taken or released, removes the whole class.
- **Checks need adversarial tests too.** The audit check could never fail, and the latency judge failed honest pages for a reason unrelated to latency. A check is tested by feeding it what it must refuse (an accepted UPDATE, a lagging page) and what it must accept (a brief repeated value).
- **Measure before tuning.** The OEE latency regression was traced with new metrics and traces that refuted three plausible causes (shared pacing, the read pool, the browser) before the real one (the judge's notion of "seen") was found. No product code changed.
- **Without CI, the gate is a discipline.** Running every CI job locally on each final commit kept the merge bar unchanged, but the evidence now lives in PR text and local result files, not in logs anyone can open. Restoring CI, or recording local results in the repository, is worth doing before the next long phase.
