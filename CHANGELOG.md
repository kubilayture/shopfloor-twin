# Changelog

All notable changes to this project are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/) from `v1.0.0`.

## [Unreleased]

### Added

- Simulator ground-truth OEE with `oee-core` (#117): `GroundTruth` keeps, per machine, the OEE inputs of every shift bucket and every UTC hour (time per state; Stopped intervals held until they close, then filed as pieces with their whole length; cycles per product and result, bucketed by their time with `shiftKeyAt`), and returns `bucketOee` per machine and shift bucket and `workCenterOee` for Cell M1 and Line A1, with fractions as `num/den` and four-decimal strings, losses, `unplanned`, `anomaly` and `provisional`. An open stop's whole length runs to the snapshot time (ADR-0021). Summary format `sim-summary/2` (new `oee` section; all other fields unchanged). Simulator control API 1.2: `GET /api/v1/ground-truth` includes the `oee` section; OpenAPI `info.version` `1.2.0`. Golden `week-01/summary.json` regenerated for the new section only (39,404 lines added; the schema line is the only changed line); `events.sha256` unchanged (`e7c69736…009b740b`), so the simulation itself is unchanged. A snapshot costs about 0.2 ms after a shift and about 3 ms after a week (response about 450 KB after a week).

### Fixed

- A CNC's first changeover with no product loaded gives cause `CHANGEOVER none→<product>` instead of `CHANGEOVER undefined→<product>`; the format is documented in `docs/simulation-model.md` and the OPC UA address-space contract. Golden week `week-01` not regenerated: a validated schedule always loads a CNC's first campaign at start, so the week never takes this path; its events (35,764 lines, `events.sha256` `e7c69736…009b740b`) and `summary.json` are byte-identical, and that hash is the baseline #117 must keep (#126).

### Changed

- The simulator's run header hashes only the simulation sections of the plant configuration (`SIMULATION_FILES`, `simulationSections` in `plant-config`), so OEE configuration never changes `configSha256` or `events.sha256`; golden `week-01` unchanged. `plant-config` cross-checks that shifts start and end on whole hours in a time zone with whole-hour UTC offsets, and that ideal cycle times are whole milliseconds (#116).

- `pnpm verify` also runs `pnpm check:dockerfiles` (`scripts/check-dockerfiles.ts`): every app's Dockerfile must copy the `package.json` of each workspace package its `pnpm install --filter` selects and the `src` of each one it needs at run time, and nothing else from `apps/` or `packages/`; a root `tsconfig.json` type-checks and lints `scripts/*.ts`; the CI `stack smoke` job sets up Node.js for the web checks and gets 20 minutes (#99).
- The MES API's response and WebSocket message schemas moved from `mes-server`'s `realtime` module to `@shopfloor/contracts` (`@shopfloor/contracts/mes-api`), so `web` parses with the same schemas the OpenAPI document is generated from (documents unchanged); the shared ESLint config gives `apps/web` browser globals and the React hooks rules (#98).
- Plan rev. 6 and ADR-0011: Claude merges after an independent review agent and a green CI; ADR-0004's merge rule superseded; PR template checklist updated (#46).
- `products.yaml` gains `componentsOperation` and per-product `reworkComponents` (#27).
- Leak-test defaults widened (sigma 0.45, limit 3.2) so that failures and rework actually occur; `leakTest.operation` and `reworkOperation` added to `process.yaml` (#25).
- Default weekly schedule raised to 1,500 VB-100 and 700 VB-200 and stock to match, so the program fills the week; shift breaks optional in the schema (#26).
- Plan rev. 5: Phases 1–6 run from a weekly production schedule file; Phase 1 plan with issues #18–#30 (#17).

### Added

- `oee-core` OEE (#116, ADR-0021): availability, performance, quality and OEE per machine bucket (`bucketOee`) and per work center from summed inputs (`workCenterOee`), with own and external availability loss, micro-stops, speed loss (may be negative) and quality loss; reduced BigInt fractions and half-up four-decimal rounding in integers (`fraction`, `toDecimal`); `null` where a ratio is undefined and an `anomaly` flag for counts without APT; open stops counted as provisional micro-stops. An ESLint rule forbids floating point in `oee-core`. `config/plant/oee.yaml` (micro-stop threshold 120 000 ms over the whole Stopped interval, `scheduledTime: shift-calendar`), loaded and validated by `plant-config`; `idealCycleMs` gives exact ideal times. `null` losses and `unplanned` counts for cycles when PBT = 0. `docs/oee-reference-cases.md`: 19 hand-calculated cases that the tests parse and check as fractions and four-decimal values; property tests for bounds, A·P·Q, loss accounting, hours summing to the shift and monotone rounding.

- Full-shift reconciliation through the whole chain (#100; Phase 4 exit criteria 1 and 3): `pnpm test:reconcile` (new workspace package `e2e`, `@shopfloor/e2e`) builds the images and starts the Compose stack under its own project (`e2e/compose.reconcile.yml`: ephemeral host ports, no restarts, fresh volumes, generated passwords instead of `.env`) in the plan's order — database and broker, MES ready, simulator idle (`SIM_AUTOSTART=false`) and gateway connected with every machine's start-up state anchored, web — then resumes the simulator at 60× from Monday 06:00 with the golden week's seed. After shift A plus 5 minutes it pauses the simulator, waits until the MES has drained and checks: time per state per machine for the shift equals the simulator's live ground truth to the millisecond, the live ground truth equals the golden week's shift A, every stored piece lies inside one UTC hour and one shift bucket, and no lost-data incident or rejected message exists. A failure prints a difference table and the service logs; `e2e/results/` holds the report, the compose log and the Playwright trace and screenshot. The run stops itself after 25 minutes with its report and logs, and removes the stack on SIGINT or SIGTERM. New CI job `reconcile` (30-minute timeout, browser cached, results uploaded unless it succeeded). `docker-compose.yml` tags the app images with `IMAGE_TAG` (default `dev`); the run uses `reconcile`.
