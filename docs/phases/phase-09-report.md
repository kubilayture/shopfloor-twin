## Summary

The owner can now steer the plant from a browser, replay what was done, read OEE per order and per line, and the stack has been hardened and then broken on purpose:

- **Order and line OEE** (P9-02 to P9-06): `oee-core` derives the bottleneck per product (ASM-01), the head time and window of every job, order OEE over the windows, first-pass yield across the routing and a throughput line OEE that may exceed 1 (`aboveOne`); the simulator writes their truth in `line-oee.json`; the MES derives, serves and pushes them; the order detail and the OEE dashboard show them, live-reconciled against the truth.
- **Console actions, timelines and replay** (P9-07 to P9-09): lot block and release, operators absent for a shift, tool breakage, each a new event variant written only when used; YAML timelines in `config/scenarios/` played headless and live with the same event log; a live run's dispatches recorded and replayed headless byte for byte.
- **Simulation console** (P9-10): `/console` behind an exact-route `/sim/` proxy with `auth_request`, an Origin check, the control-API token injected by nginx and the `edge` network for trusted proxy headers.
- **Derived work** (P9-11): incremental SPC derivation, proven equal to the whole derivation, and hold scopes rebuilt on change.
- **Hardening** (P9-12 to P9-15): OPC UA SignAndEncrypt with pinned leaf certificates and two users; MQTT dynamic security with every user bound to one client id; an HTTPS-only front with a per-stack, name-constrained dev CA and `__Host-` cookies; MES, gateway and database unpublished; login throttling per (account, address) with a global delay that never locks; `docs/security-review.md`.
- **Proof** (P9-16 to P9-18): `pnpm test:resilience` (R1–R3), the observability profile (Prometheus, Grafana), `pnpm test:perf` (P1–P3, T1–T6) with new ingest lag metrics.
- **Fixes:** P9-F1 (line OEE finality across simulator restarts) and P9-F2 (a `pki` rerun dropped OPC UA pins from a running trust index).

**Exit criteria: 8 of 9 met and 1 partly met, by local runs on `86a1757`.** Criterion 4 (the console) is partly met: every refusal and every action reaching the simulator is proven through `/console`, but the effects the criterion names (a starved OP10, a raised alarm, `NO-OPERATOR`) are proven at the control API, not observed through the console, and the lot-block effect is tested on ASM-01's seal-kit lot, not on OP10. Criteria 5 and 6 are met by methods that include coordinator decisions awaiting the owner's review (the R3 schedule; ADR-0040's five decisions). The closing gate passed in full: `pnpm gate`, `pnpm test:resilience` twice in a row, `pnpm test:perf`, `pnpm test:trace-perf`, three uncached `pnpm verify` runs and `pnpm test:console`, all on the same commit, nothing rerun.

## Defects found, and how each was fixed

Every pull request had an independent review (ADR-0011), and no PR was approved in its first round. As in Phases 5 to 8, the findings that mattered came from a reviewer running something: a probe against the real component, a crafted interleaving or a mutant of the code under test.

- **Gate hygiene (#248):** a busy spin and an unbounded wait when breaking a stale lock; a lock freed under a running suite when its wrapper was killed; **a live lock broken by a waiter in another locale or time zone** (`ps -o lstart` follows `LC_ALL` and `TZ`). Fixed with process-group records, start times compared as instants in `LC_ALL=C TZ=UTC`, and 49 tests including cross-locale processes.
- **Order and line OEE (#247, #251, #252, #255, #258, #266):** inclusive cut-offs that made an order look final with its last cycle unplanned (`groundTruth()` at exactly the event time); a job queue built from facts alone could finalise a wrong window (the queue contract, H16); old-epoch jobs never final; an hour made final from one pack of three by an old epoch's progress ahead of the clock; a bucket with PCK-01's run-1 packs over ASM-01's run-2 pieces called final; an order detail stuck provisional across completion. Each is a regression test now.
- **Timelines and replay (#250, #253):** a cue between sparse events fired up to 1 s late and a speed cue moved the paced clock backwards; quadratic reads of a 12,000-entry timeline; an event log write error that threw from a timer; **an injection and an action of one millisecond replayed in the wrong order** (`inputOrder`); a replay longer than the live run (`endAfterEvents`, `stopAt`).
- **Console (#256):** the event WebSocket outlived a logout; a client's `X-Original-Method` passed through `/api/`; **the `edge` network's bridge gateway lay inside the trusted subnet** (`inhibit_ipv4`).
- **SPC (#259):** a retest resumed the chart from its part's first test and was counted `late`; the month's late p95 first missed its budget (21.9 ms), fixed by a batched update.
- **OPC UA (#260):** **every server variable was writable by any session** (node-opcua's default access level); pins from before #239 survived in a persisted volume; a pinned leaf acted as a CA; a certificate without `clientAuth` was accepted. P9-F2 (#265, from the review of #264): a `pki` rerun dropped unchanged pins from a running server's trust index (node-opcua-pki's watcher; an upstream report is drafted in the log, not filed).
- **HTTPS (#262):** the owner's macOS trust of the dev CA was for every purpose (now SSL only); the MES's Origin guard ignored the scheme (now checked against `X-Forwarded-Proto` from `edge`).
- **MQTT (#261):** **Mosquitto lets an unbound user take a bound id's session**, so every user is bound; a user name matched as a pattern; `mosquitto_ctrl` exiting 0 for a missing client; the first template refused subscriptions the old broker granted (caught by the parity test).
- **Login (#264):** `Retry-After` 31 (the clock read before the row lock); a login flood starving the identity pool; unkeyed buckets letting one address lock everyone out; queued hashes pushing a victim's login to 37 s.
- **Resilience (#268):** **a database restart killed the MES** (pg-pool listened for errors on idle clients only); R3's window anchored on the wrong time; the gap comparison as a set instead of a multiset.
- **Performance (#269):** four judges that could not fail or failed on correct behaviour (decisions 1–5 above); the live rate computed over the wrong span ("17/s" instead of 13.35).

**The closing gate found no defect:** no run failed, nothing was rerun, so no issue was opened.

## Lessons

- **Ask what would make a check fail before trusting it pass.** Phase 9's proof suites had five judges that could not fail or failed on correct behaviour (a bounded gauge, a dead container, a feed at 1× called 3×, a fault in a break, a buffer that is always in use). Each was found by asking that question, and each is now recorded as a decision with its number.
- **A fault schedule is part of the test.** R3's first schedule lost nothing, and the reason (a live OPC UA session survives an outage; loss comes from new sessions) is a finding about the system, not only about the test.
- **Default settings are attack surface.** node-opcua made every variable writable and offered X.509 user tokens; Mosquitto let an unbound user take a session; node-opcua-pki's watcher dropped a fingerprint two files shared. None was in the plan, all were found by a reviewer probing the real component.
- **A throttle is itself a denial-of-service tool.** Each layer added against password guessing (a lock, a global delay, buckets, a ceiling) opened a way to keep honest users out, until the design kept a path back in (a recent address, an admin's reset) and the remaining cost was written down.
- **Bind identity to what the attacker can't forge.** The client address from nginx is believed only on a network only nginx is on; an MQTT user only under its own client id; a cookie only on HTTPS for one host; a browser only to one key.
- **Determinism needs the point, not just the time.** Replaying a live run needed the number of events processed before each input, an acceptance order across input kinds, and the stop point; the simulation time alone was ambiguous within a millisecond.
- **Keep every check that isn't a gate step in its own record.** Resilience, performance, trace performance and the console run are separate commands; the closing gate runs them on one commit so their evidence has a commit attached.
- **Disk and load are shared state.** The heavy lock held through the whole phase: no two heavy suites overlapped, and none of Phase 8's load flakes came back.
