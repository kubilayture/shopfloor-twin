## Summary

Phase 10 built nothing new into the plant or the MES. It made the system releasable and checkable by someone else:

- **A fresh clone starts with one command line** (P10-02): `sh scripts/stack-init.sh && docker compose up -d --wait`, the README's quick-start block, run verbatim by `pnpm test:fresh-clone` on a clone of the commit in a Node-free shell, isolated from the owner's stack by process environment.
- **Property seeds are recorded** (P10-01): every `pnpm verify` prints one fast-check seed per workspace, and `FC_SEED` replays it.
- **The documentation is current** (P10-03, P10-04, P10-05): README, runbook, STATUS, the API references, the glossary, a documentation index, and C4-style architecture views that `scripts/check-architecture.ts` checks against the code in every `pnpm verify`.
- **A scripted demo and its recording** (P10-06, P10-07): eight scenes that assert what they show, and a headless recording of that same test (4.79 MiB, 6 min 35.0 s).
- **The final report** (P10-08) with each success criterion's proof and probe, the Sparkplug B decision (ADR-0041: not in v1.x), and the register of 69 decisions awaiting the owner; **the release mechanics** (P10-09): one product version `1.0.0`, the CHANGELOG, the runbook's "Releasing".
- **Three fixes:** P10-F1 (#288, tests timing out under `verify`'s default concurrency), P10-F2 (#295, measured values at the characteristic's precision and plant versus wall time on the screens) and P10-F3 (#300, the production audit counting a test helper's runtime dependencies).

**Exit criteria: 8 of 8 met, by local runs on `a32d71a`.** Criterion 3 is met by stating that **success criterion 6 is not met**, pending the owner; that is the one v1 criterion Claude can't meet. Success criteria 1–5 are met on the candidate, each with a falsifiability probe that failed as required; SC2 by the local gate, not CI, with the provenance of two golden snapshots pending the owner (#140, #172). The closing gate passed in full on `a32d71a`: `pnpm gate`, `pnpm test:resilience` twice in a row, `pnpm test:perf`, `pnpm test:trace-perf`, `pnpm test:console`, `pnpm demo`, `FRESH_CLONE_NO_CACHE=1 pnpm test:fresh-clone`, three uncached `pnpm verify` runs with their seeds and `pnpm audit --prod` (no known vulnerabilities), one after another, nothing rerun; and the five falsifiability probes failed at the assertions that guard their properties.

## Lessons

- **A closing gate is a test too, and it can fail.** The first run on `dd78dcd` passed eleven suites and failed the twelfth; the failure was in a check nobody had run since a day before. Stopping, reporting and moving the candidate cost a second four-hour run, and is the reason the report can say the gate is not a formality.
- **A production audit counts what you declare, not what you ship.** No image contained Vitest, but a test helper declared it as a dependency. Declaring the consumer's tools as peers says what the helper needs without claiming it ships them.
- **Advisories arrive on their own schedule.** Both were published during the phase, after the last clean audit. An audit belongs in the closing gate for that reason, not only in the phase that last touched dependencies.
- **Define the claim before proving it.** "One command" and "same seed, same bytes" needed written definitions (one command line whose first part runs once; the local gate, not CI) before a test could prove them, and both are marked for the owner rather than silently reinterpreted.
- **A probe must fail at the right assertion.** SC2's report rule and SC5's "every second entry" came from asking where a broken property should show up, not only whether something goes red.
- **Isolation by environment beats editing files.** The fresh-clone test ran the README verbatim against a Compose file named for the owner's project, and never touched it, because every Compose call got the project, tag and ports from its environment.
- **A demo that asserts what it shows can be recorded honestly.** The recording is the test with a camera on; the only additions are holds without actions.
- **Two clocks need two labels.** A 60× plant clock and the wall clock on one screen read as one clock until each time says which it is.
- **The owner's review moved to the end, and it is large.** 69 decisions wait for one person. The register makes it answerable, but a later project would do better to keep the sign-off inside each phase.
