- #228 (P9-01, branch `chore/228-gate-hygiene`, wave A): gate and test hygiene.
  - **Heavy-suite lock** (`@shopfloor/test-kit/heavy-lock`, `scripts/heavy.ts`): the directory `~/.cache/shopfloor-twin/heavy.lock` with `holder.json` (PID, command and checkout, start time, token), made complete in a staging directory and renamed into place (rename onto a non-empty directory fails, so taking it is atomic and a lock never exists without its holder). A waiter prints the holder once and polls every 2 s up to `HEAVY_LOCK_TIMEOUT_MS` (default 3 hours), then fails naming it. Stale only on `ESRCH` (`EPERM` and any other answer count as alive), broken under a guard file made by hard link so two waiters can't remove each other's fresh lock; release renames the directory away before deleting it. Children inherit it through `SHOPFLOOR_HEAVY_LOCK`. Taken by `pnpm gate` (in-process), `pnpm verify`, `pnpm test`, `pnpm test:e2e`, `pnpm test:reconcile`, `pnpm test:trace-perf` (through `scripts/heavy.ts`) and Playwright (its global setup, inherited under the reconciliation). `pnpm verify`'s steps moved to `verify:steps` so the lock wraps them; `pnpm verify --concurrency=1` still passes the flag to turbo.
  - **Disk:** holding the lock (not when inherited), a command refuses to start below 25 GiB free on the host (`statfs` of the repository) or 15 GiB in Docker's data root (`df -Pk /` in a throw-away, network-less container of the broker's image, parsed from the right by the capacity column), exit 2 naming the disk. The gate records both figures.
  - **Ephemeral smoke ports:** the smoke reads every host address back with `docker compose port` (on the default ports too); with `SMOKE_EPHEMERAL_PORTS=1`, which the gate sets, it adds `e2e/compose.ephemeral-ports.yml` (MES, web, ERP mock, gateway and control API on ephemeral ports, database, broker, OPC UA and Modbus unpublished, restart policies unchanged) and asserts no default port and none of the unpublished ones is on the host.
  - **Cleanup per run:** the gate already removed its project's volumes and its tag's images; `pnpm test:reconcile` and `pnpm test:trace-perf` now remove the images they built at the end, pass or fail (`RECONCILE_KEEP_IMAGES=1`, `TRACE_PERF_KEEP_IMAGES=1` keep them; the gate passes the first and removes them itself after recording the digests), never the tag `dev`. The BuildKit cache is pruned to 10 GiB after each build (`docker builder prune --force --keep-storage 10GB`) and at the gate's end.
  - **Limits:** database 1 GiB and 1.5 CPUs (above its 512 MB, 2-CPU tuning), broker 128 MiB and 0.5 CPU, and (after the review below) the one-shot `migrate` step 256 MiB and 0.5 CPU, so every service has limits (S8).

  - **Review of PR #248** (changes required): (1) `breakStaleLock` crashed when the guard vanished between the failed link and its read (the reviewer: 9 of 24 processes); ENOENT now returns false, and both guard unlinks tolerate it. (2) A break that didn't succeed (guard held by a live process) looped without sleeping or checking the deadline (95 % CPU, no timeout); now only a successful break retries at once, and the stale message is printed once per token. (3) `migrate` had no limits, so "every service" was false; it has 256 MiB and 0.5 CPU. (4) The lock stays alive while any process group its holder recorded runs (`group-<pgid>` files; `scripts/heavy.ts` records its command's group, the gate each job's), so a SIGKILLed wrapper no longer frees the lock under a running suite. (5) The holder records the boot time and its own process start time (`ps -o lstart=`): a lock from an earlier boot or a reused PID is stale; a lock directory without a valid `holder.json` is waited for and stale after 60 s; the runbook has a recipe for a wedged lock. (6) The lock path comes from the account's home directory (`os.userInfo().homedir`), not `$HOME`. (7) The disk probe never pulls (`--pull never`) and says whether the image is missing or Docker is down; the runbook says heavy commands refuse to start without Docker. (8) The BuildKit prune is `--all --keep-storage 10GB` (without `--all` the cap needn't hold) and the runbook says it is machine-wide; `RECONCILE_KEEP_IMAGES` and `TRACE_PERF_KEEP_IMAGES` are next to their `SKIP_BUILD` options; the manual smoke takes no lock. (9) `blockedBy`'s `holding` counts only a granted `RowShareLock`. Mutation checks: without the ENOENT return the vanishing-guard test fails; with the old unconditional `continue` the busy-spin test never returns (the runner hung and was stopped).
  - **Re-review of PR #248** (the round-1 fixes verified; new findings): **A (blocker)** `ps -o lstart=` follows `LC_ALL` and `TZ`, so a holder and a waiter in different locales or zones read different texts and the waiter broke a live lock (the reviewer: after 17 ms, `LC_ALL=C` against `tr_TR.UTF-8` or `TZ=UTC`); `ps` now runs with `LC_ALL=C`, `LANG=C`, `TZ=UTC`, the texts are compared as parsed instants, and times that can't be compared count as alive. **C** an exact boot-time comparison could break a live lock after a clock step or `btime` jitter: the boot time is consulted only when start times can't be compared, and then only a difference over 5 minutes is another boot. **B** each `group-<pgid>` file holds the leader's start time; a group whose PGID now names a process started at another time is gone. **Guard age:** a break guard older than a minute is removed even when its writer's PID answers (reused). Tests: 49 in `heavy-lock.test.ts`, among them a Turkish-locale, Istanbul-time holder process checked alive by waiter processes in C/UTC, en_US/New York and tr_TR/Tokyo (fails without the fixed environment), times that can't be compared, start-time parsing with single-digit days, the 5-minute boot tolerance and a matching start time beating a boot difference, a reused PGID, and an old guard with a live writer PID.
