## Summary

The plant now runs from orders, and every MES write has a known user:

- **Identity** (#168, #169, #170): users with the master plan's five roles, a permission matrix shared by MES and web, server-side sessions in an `HttpOnly`, `SameSite=Strict` cookie, scrypt hashes, lockout, a login screen; every route and the WebSocket need a session (`MES_AUTH=on` by default). The MES connects as `mes_app`, a database role that owns nothing, so it can no longer disable an audit trigger; one append-only `identity.audit_log` replaces the three module audits, with their old rows backfilled.
- **ERP mock** (#171): a REST change feed of orders with routing and BOM, lots from the same file the simulator stocks, idempotent confirmations and status messages.
- **Order-driven simulator** (#172): production mode `orders`, an idempotent OPC UA method `LoadOrder`, job facts in the device sequence, the cause `NO-ORDER`, ground truth per order and unit (`sim-summary/4`), golden scenario `orders-01`.
- **Command path** (#173, #174): MES outbox → UNS `cmd/load-order` → gateway → `LoadOrder` → `cmd-res`, at least once with device dedup, outcomes the gateway can't see settled after expiry, never guessed; proven exactly once per command and per order by the device's job facts.
- **Orders and execution** (#174, #175): import, release, dispatch, re-dispatch only from settled answers, every part tracked through OP10–OP50 with rework passes, completion only when no unit can return, one final ERP confirmation per operation.
- **Screens** (#176, #177): orders list and detail with supervisor actions, and an operator terminal with crew sign-on, start, pause, resume, scrap coding and sign-off.
- **End to end** (#178): a second live reconcile pass running `orders-01`'s shift A in orders mode through the ERP mock, MES, gateway and simulator, Playwright role and terminal checks, and `pnpm gate`.

All six exit criteria are met by local runs. The closing `pnpm gate` passed on this branch (see "The closing gate").

## Review findings that mattered

Every pull request had an independent review (ADR-0011). As in Phases 5 and 6, the findings that mattered came from a reviewer running something: a probe over real HTTP, a `psql` session against a migrated database, a crafted interleaving, or a mutant of the code under test.

- **Plan (#167, PR #180), three rounds, before any code:**
  - **B1, continuous aggregates:** only an aggregate's owner can refresh it, and the refresh can't run inside a function, a `SECURITY DEFINER` procedure or a transaction block (probed). So `mes_cagg` owns the aggregates and `mes_app` refreshes after `SET ROLE mes_cagg`, with the accepted cost that it could drop derived data, never an audit table.
  - **B2, a second job:** a retried method call that the device had executed made two jobs without device dedup (probed with a client timeout). The device checks its dedup table first, refuses stale epochs and expired commands itself, and re-dispatch waits for a settled answer.
  - **B3, live equal to headless:** dispatches are applied after `line.start` and before injections in both runs, and the live test waits for every device confirmation before injecting.
  - **M1:** `REASSIGN OWNED` can't move objects from the bootstrap superuser, so `migrate` moves them one by one.
- **ERP mock (#171, PR #181):** the `Idempotency-Key` was not bound to the body (now refused 422 unless built from it), duplicate confirmations, the status key's missing revision, `feedId`, hardening; approved on re-review.
- **Identity (#168, PR #182), one blocker:** an `Upgrade` header bypassed the write guards (B1); parallel logins outran the lockout (H1); password-change failures, login buckets apart from the write bucket, `MES_WRITES=off` locking users out of login, the WebSocket's must-change gate. Fixed and re-probed over real HTTP. L5 (cookie tossing on localhost) accepted and documented.
- **Simulator (#172, PR #183):** transient and permanent `LoadOrder` refusals were not told apart (medium) and five lows; fixed.
- **Gateway (#173, PR #184), one high:** definitive answers were reused across device epochs (the gateway's file outlives a run, command ids are deterministic); the epoch is now in the result key. Also the settle call's acceptance (now `accepted`, counted), the `seqAfterExpiry` boundary (`≤`), the `cmd-res` precedence rule written down (ADR-0029), the settle gated on the device's own clock, and (`305e13e`) an `unknown` never overriding a definitive answer.
- **Database roles (#169, PR #185):** the grants test widened to PUBLIC, sequences and function ACLs; `ensureRoles` resetting role attributes and memberships; the legacy test from `0015` and `0016` with a whole-catalog comparison against a fresh database; PUBLIC `CONNECT`/`TEMP` revoked; the SCRAM verifier computed client-side so no password reaches the server log.
- **Web login (#170, PR #186):** dot-segment redirects normalising to `//host` (M1), pushed alarm and shift copies not reset after a same-user re-login (M2, the Phase 6 lesson again), the web's idle deadline trailing the MES's (M3), missing tests for the risky flows (M4).
- **Orders (#174, PR #187), three rounds:**
  - round 1: one duplicate routing operation poisoned every import (high: now a savepoint per feed entry); `command-conflict` treated as settled; run-ended accounting relying on late facts; a CNC blocked for ever by unpublished attempts; safety not proven by tests (a property test and four more e2e cases added);
  - round 2: the `seqAfterExpiry` bound compared two clocks (now the stored sequence number recorded before the first publish), refused publishes looped (now an incident and backoff).
- **Execution (#175, PR #188), high:** completion ignored open routing suspects: an order could complete early while a fact was still in an open gap, and never complete after a gap was written off. Lost units counted as done while a lagging machine could still report; units not marked lost after an epoch change during MES downtime; a failed tick dropped its pending facts. Fixed with tests, more shuffled seeds and restart and gap tests.
- **Web orders (#176, PR #189), high (an MES bug):** `dispatched` stayed 0 after an acceptance because the order's version and push did not follow blank-count changes; the action form was not keyed (M2).
- **Terminal (#177, PR #190):** the crew check ran outside the write transaction (orphan intervals, rewritten history, a late cleanup closing new work) and the terminal view's cost grew with history; the re-review found the memo expiring only by time. All fixed with locks inside the write and a memo cleared on every execution change.
- **End to end (#178, PR #191), three rounds:**
  - round 1: the completed-order set was only `≥ 3` (now exactly the golden run's), no signal cleanup in the gate, self-comparisons and vacuous paths; exit criterion 3's last case got both ways out end to end;
  - **round 2, by mutation testing:** the reviewer mutated the MES so that it ignored a `duplicate` answer, and case (a) still passed; case (b) passed only because an earlier test had prepared its state. Case (a) now injects the `duplicate` while the fact is still held, so the answer alone must settle the job; (b) seeds its own precondition. Both fail under the reviewer's mutants when run alone;
  - two defects found by the live runs themselves: the execution module read the machines' final-through after rebuilding units, so a washer cycle stored in between raised a false `routing-violation` (and could have completed an operation early); now a round reads progress first, in ingest's queue (ADR-0031 note, a test reproducing the interleaving). And the raw request helpers sent DELETE bodies unframed (nginx 400 on the next request).

## Lessons

- **Prove exactly-once with the device's facts, not with the transport.** MQTT QoS 1 and retries give at least once; the device's dedup table makes a repeat harmless, and the job fact in the device sequence is the proof that counts. Every layer that can't know an outcome says `unknown` and carries what lets someone settle it later (`seqAfterExpiry`).
- **Probe the platform before planning on it.** Three plan blockers (aggregate ownership, `REASSIGN OWNED`, the retried method call) were found by small probes against TimescaleDB and node-opcua, not by reading documentation. Each would have cost a redesign after merge.
- **A test that can't fail is not evidence; mutate the code to find out.** The review of PR #191 showed with two mutants that exit criterion 3's hardest case passed whether or not the MES read the answer it was about. Running the reviewer's mutants against the fixed tests is now the bar for a safety test.
- **Read the bound before the data, again.** The live run's false routing violation was the Phase 5 and 6 bug class in a new module: final-through read after the work it judges. "Capture the bound first" now holds across modules, through ingest's queue.
- **Enforce the switch in steps.** `MES_AUTH=off` in #168, old actor fields accepted in #169, enforcement and every test's login together in #170 kept `main` green through an authentication change that touched every client.
- **A record beats reconstruction.** `pnpm gate` prints which commit got which job; the gate exceptions of this phase were found in PR prose, where they are easy to miss. Recording the gate per commit, and closing the phase with one full gate, makes the evidence checkable.
- **Keep the log the plan promises.** The phase ran without its log, so the wave A checkpoint and the per-PR lessons live only in STATUS and PR bodies. The next phase should keep `phase-08-log.md` from the first merge.
