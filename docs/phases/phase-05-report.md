## Review findings that mattered

Every pull request had an independent review (ADR-0011). The findings below changed the design or caught a defect before merge, not only the wording. Most were found because reviewers _ran_ something: a throwaway TimescaleDB, a Python recompute, a disposable stack, `app.inject` probes, an adversarial page.

- **Plan (#125), three blockers fixed before any code:**
  - **Continuous-aggregate watermark holes.** A continuous aggregate has one watermark. Refreshing a later hour hid every earlier hour that was never refreshed, and every later change below the watermark, including a new epoch at an earlier time. The reviewer showed this on TimescaleDB 2.30.2. Fix: every change below the watermark marks its hour dirty, and the refresh is contiguous from the earliest dirty hour.
  - **Config hash.** Adding `oee.yaml` would have changed the run header's `configSha256`, and with it the golden `events.sha256`. Fix: only the simulation sections are hashed, and a test proves it.
  - **Record key collisions.** Down or Setup across a shift end gives two records with the same interval start. Fix: records are keyed by their start within the bucket.

  The review also found the `CHANGEOVER undefined→…` cause (#126).

- **`oee-core` (#128):** cycles in an unscheduled bucket leaked into speed and quality loss, and inflated P and OEE in sums over a day. Now every loss is `null` when PBT = 0, and off-shift cycles are reported apart as `unplanned`.
- **Finality (#129):** a commit applied while its acknowledgement failed, followed by a cursor reload, could leave a state fact unapplied and its pieces flagged final. A jump in the settled part now compares ingest's state-fact count with the track's. Also: a closed epoch's incidents reach its final hours, and history write-offs are logged and counted.
- **Aggregates (#132), blocking:** an hour could read final with its new revision while `cycle_hourly` still held the old count, because ingest marked the hour dirty only after equipment's listener had committed. Ingest now marks every hour of a message before it notifies anyone. Failed refreshes back off and retry.
- **Records (#131):** the record delete scanned every record of the epoch on each in-order fact (O(n²)); it is now bounded on its key. The read path gained indexes, `LOSS_STATES` got one source, and an empty cause counts as null.
- **OEE module (#133), two blocking rounds, both about finality and revisions:**
  - **A final hour changed without a revision.** A stop whose end came from a fact that arrived before a missing one counted as settled. After an incident released finality, a late fill turned a 10.5-min stop into a 50-s micro-stop, and the earlier hour changed its A and P with revision 0. Now such a stop is open until "final through" passes its end, and a settled stop's class change raises the revision.
  - **A false revision on an in-grace fill.** The re-review found that the fix judged "settled" against the bound after the late fact had moved it, so a fill within the grace period raised a false revision on an hour that was never final. It now uses the bound from before the fact.

  Also fixed: the Pareto was silently capped at 2,000 records; finality is now sampled race-free around the reads (refresh generations); the 128-bucket count is asserted.

- **Coding writes (#134):**
  - **The smoke writing into the owner's database.** The stack smoke's write took the first closed record, codings or not, replaced and cleared its codings, and left permanent audit rows. On a database the owner keeps, that deletes an operator's work. Smoke writes are now opt-in (`SMOKE_WRITES=1`, set in CI) and only touch a closed, final, uncoded record, re-checked before each PUT.
  - **Write vs re-cut race.** A coding could end up outside its record and count twice in the Pareto. The write now reads its record `FOR SHARE`.
  - Also: `HTTP_ALLOWED_HOSTS=*` is refused while writes are on, and ADR-0023 records that the table owner can disable the audit trigger.
- **Web (#135), blocking: stale-draft overwrite.** A `recoded` push arriving mid-edit gave the draft the newer version but kept its old codings, so a save silently replaced another operator's coding. A draft now keeps the version and codings it started from, and a changed record shows a conflict that must be reloaded. Also fixed: past OEE buckets could show a stale pushed value, and sibling records' new versions are now pushed as `updated`.
- **End to end (#136): the latency-judging loophole.** The reviewer simulated adversarial pages against the real judge. A page lagging 4 s that slipped in values the polls never saw passed the latency judgement alone. The value floors (at most 5 % unseen values, 95 % snapshot agreement, an agreeing snapshot per id) moved into `pageValueProblems`, with a unit test for exactly that page. The frozen-page ratio went back to a half, and the Pareto check can no longer pass vacuously.

## Known issues and carry-overs

- **The smoke wrote into the owner's dev database once.** The stack smoke in #121's first local run wrote one smoke coding and its clear into the owner's default dev database (Compose project `shopfloor-twin`), so `equipment.downtime_audit` there holds those two rows. They are permanent by design: the audit's trigger refuses UPDATE, DELETE and TRUNCATE. Since the #121 review, smoke writes are opt-in (`SMOKE_WRITES=1`, set in CI only), and the runbook shows a disposable `COMPOSE_PROJECT_NAME` for local runs. `pnpm stack:reset` removes the rows with the volume, along with all other data.
- **The audit trigger binds the MES's connection, not the table owner.** The MES connects as the role that owns its tables, so it could `ALTER TABLE … DISABLE TRIGGER`. Separate roles come with identity and hardening (Phases 7 and 9; ADR-0023).
- **Writes are unauthenticated** until identity (Phase 7). `codedBy` is free text, audited with `authenticated: false`. The same-origin check ignores the scheme, which is acceptable on loopback only.
- **One global write rate limit** (10/s, bursts of 20). Behind nginx every request comes from nginx, so a per-client limit means nothing; one noisy client slows everyone's writes. At plant-floor rates it never triggers.
- **`prom-client` is deprecated** upstream in favour of `@prometheus-io/client`: a follow-up for ADR-0012, still open.
- **Retention and compression:** there are still no policies on the hypertables. A retention policy must now also respect the continuous aggregates (their materialisation and invalidation), the final hours in `equipment.bucket_finality`, and the append-only audit (ADR-0018, ADR-0022).
- **Open from the log and the ADRs:**
  - A re-cut that moves a loss interval leaves the moved-out time of a coding orphaned, so the operator codes it again. The audit shows what was lost.
  - Aggregate dirty hours live in memory. The start-up catch-up covers a crash, but a write that bypasses the modules is materialised only at the next start.
  - The start-up cycle-count check reads every final hour. That is cheap now and can be bounded later.
  - Work-center OEE is time-weighted, not line throughput. Throughput-based OEE waits for orders (Phase 7).
  - Vite's 500 KB chunk warning: the ECharts chunk (lazily loaded) and the main chunk are both just over it. Splitting the main chunk by route is the first lever if load time matters.
- **Carried from Phase 4:** one transaction per message in ingest; client-id takeover on the broker (Phase 9); broker persistence only up to the last autosave.
- **Phase 6 (alarms and shifts) inherits:**
  - the `oee` module and the shift API (`/shifts`, `/shifts/current`, `/shifts/{date}/{shift}/oee`), for a shift report whose totals must reconcile with OEE data;
  - final, revised buckets, so a report can tell final from provisional and revised values;
  - the guarded, audited write path (ADR-0023), the pattern for acknowledging and shelving alarms;
  - push topics with per-key pacing, and the Playwright latency judge with its value floors;
  - `pnpm test:reconcile` and the golden-week reconciliation, to be extended to alarms.
- **Owner items, deferred to the owner:**
  - sign off Phase 5 (v1 success criterion 6) and Phase 4;
  - install the Renovate GitHub app (since Phase 0);
  - raise the Docker VM (Colima) to 4 GiB: the full stack's limits add up to about 2 GiB, and the Testcontainers suites run beside it;
  - run `pnpm stack:up` on their machine and look at `/oee` and `/downtime` (optional; no exit criterion depends on it).

## Lessons

- **Probe the database before designing around it.** The continuous-aggregate watermark behaviour (one watermark per aggregate; it moves to the end of the last bucket _with data_ and never back) was found by running TimescaleDB in the plan review and in #118, not from the documentation. The design (dirty hours, a contiguous window, a "covered" end of its own) follows from those probes.
- **Finality and revisions are where the bugs were.** Three blocking findings in #129, #132 and #133 were about something reading final too early or changing without a revision. Each was found by ordering events adversarially: a late fill after an incident, a fill within the grace period, a listener running before a dirty mark.
- **Exactness is cheap when it is designed in.** Integer milliseconds, BigInt fractions and half-up rounding in integers made "equal to four decimals" an equality, not a tolerance. A lint rule keeps floating point out of `oee-core`.
- **The reconciliation can't catch a shared definition bug.** The simulator and the MES both use `oee-core`, so independent checks guard the definitions: hand-calculated reference cases, checked with Python, and in two reviews a Python recompute from the raw event log (5,012 comparisons for #117; 8,290 records for #119).
- **A judge must be tested against cheaters.** The first dashboard check would have passed a page 4 s late. Test a judgement with pages built to fool it: frozen, lagging, slow, wrong by 0.0001. Honest pages alone don't show whether it can fail.
- **Tooling that writes must never default to a database someone keeps.** The smoke's first write into the owner's dev audit is permanent. Write checks now need an explicit opt-in and a disposable project.
