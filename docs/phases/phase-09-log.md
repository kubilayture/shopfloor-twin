- #228 (P9-01, branch `chore/228-gate-hygiene`, wave A): gate and test hygiene.
  - **Heavy-suite lock** (`@shopfloor/test-kit/heavy-lock`, `scripts/heavy.ts`): the directory `~/.cache/shopfloor-twin/heavy.lock` with `holder.json` (PID, command and checkout, start time, token), made complete in a staging directory and renamed into place (rename onto a non-empty directory fails, so taking it is atomic and a lock never exists without its holder). A waiter prints the holder once and polls every 2 s up to `HEAVY_LOCK_TIMEOUT_MS` (default 3 hours), then fails naming it. Stale only on `ESRCH` (`EPERM` and any other answer count as alive), broken under a guard file made by hard link so two waiters can't remove each other's fresh lock; release renames the directory away before deleting it. Children inherit it through `SHOPFLOOR_HEAVY_LOCK`. Taken by `pnpm gate` (in-process), `pnpm verify`, `pnpm test`, `pnpm test:e2e`, `pnpm test:reconcile`, `pnpm test:trace-perf` (through `scripts/heavy.ts`) and Playwright (its global setup, inherited under the reconciliation). `pnpm verify`'s steps moved to `verify:steps` so the lock wraps them; `pnpm verify --concurrency=1` still passes the flag to turbo.
  - **Disk:** holding the lock (not when inherited), a command refuses to start below 25 GiB free on the host (`statfs` of the repository) or 15 GiB in Docker's data root (`df -Pk /` in a throw-away, network-less container of the broker's image, parsed from the right by the capacity column), exit 2 naming the disk. The gate records both figures.
  - **Ephemeral smoke ports:** the smoke reads every host address back with `docker compose port` (on the default ports too); with `SMOKE_EPHEMERAL_PORTS=1`, which the gate sets, it adds `e2e/compose.ephemeral-ports.yml` (MES, web, ERP mock, gateway and control API on ephemeral ports, database, broker, OPC UA and Modbus unpublished, restart policies unchanged) and asserts no default port and none of the unpublished ones is on the host.
  - **Cleanup per run:** the gate already removed its project's volumes and its tag's images; `pnpm test:reconcile` and `pnpm test:trace-perf` now remove the images they built at the end, pass or fail (`RECONCILE_KEEP_IMAGES=1`, `TRACE_PERF_KEEP_IMAGES=1` keep them; the gate passes the first and removes them itself after recording the digests), never the tag `dev`. The BuildKit cache is pruned to 10 GiB after each build (`docker builder prune --force --keep-storage 10GB`) and at the gate's end.
  - **Limits:** database 1 GiB and 1.5 CPUs (above its 512 MB, 2-CPU tuning), broker 128 MiB and 0.5 CPU, and (after the review below) the one-shot `migrate` step 256 MiB and 0.5 CPU, so every service has limits (S8).
